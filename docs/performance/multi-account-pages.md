# 多账号页面性能分析（2026-09-17）

基线提交：`d109215a3e1e35663aaa60fd96d4e143304ca146`。范围为账号列表、模型列表、密钥列表和 popup。

## 已修复的重复工作

| 场景 | 优化前 | 优化后 |
| --- | --- | --- |
| 模型／密钥页首次加载账号数据 | 加载状态变化使初始化 Effect 再执行，读取和投影账号快照 2 次 | 1 次；显式重新加载仍生效 |
| 账号列表／popup，关闭预估今日收入 | 首次加载及定向更新仍读取、解析整份余额历史 | 不读取余额历史；开启功能时照常计算 |
| 一批通知更新 100 个账号 | 100 次单账号查询，每次读取完整账号存储 | 读取一次，再按通知中的 ID 提取；保留并发代次检查及缺失账号回退 |
| 全账号密钥页展开大量分组 | 所有账号及其密钥卡片同时挂载 | 超过 20 个分组时按窗口可见区域挂载 |

以上四个问题分别先由失败的 Hook／浏览器测试复现，再实现修复。

## 浏览器测量

使用项目构建的 MV3 扩展、隔离的 Chromium 配置及模拟接口。分别保存 10／100 个账号，每个账号包含 365 天余额历史；所有账号在同一个模拟站点，20 个模型、1 个密钥。关闭打开时刷新和自动签到。没有使用真实账号。

以下是本机最后一次顺序运行的结果，不是统计置信区间或真实站点延迟承诺。

| 入口 | 10 账号可用时间 | 100 账号可用时间 | 100 账号页面 DOM 元素 |
| --- | ---: | ---: | ---: |
| Popup | 967 ms | 824 ms | 591 |
| 账号列表 | 870 ms | 851 ms | 806 |
| 全账号模型列表 | 1,065 ms | 1,838 ms | 1,004 |
| 全账号密钥列表，并全部展开 | 1,548 ms | 7,186 ms | 972 |

“可用时间”从导航开始，包含测试辅助函数的 300 ms 稳定等待。账号／popup 等到账号出现；模型页等到首个模型出现，不代表所有目录加载完毕；密钥页等到全部账号密钥计数完成，再点击全部展开。密钥页最后一轮的“全部展开”交互单独耗时为 10 账号 387 ms、100 账号 510 ms。

密钥分组虚拟化前后，在同样的 100 账号场景中：

| 指标 | 虚拟化前 | 虚拟化后（最后一轮） |
| --- | ---: | ---: |
| 导航到全部展开可用 | 13,436 ms | 7,186 ms |
| 页面 DOM 元素 | 12,529 | 972 |
| CDP ScriptDuration | 9.40 s | 5.20 s |
| CDP TaskDuration | 11.96 s | 6.07 s |

虚拟化前的测量已经包含前两项账号读取优化，因此此表主要比较密钥分组渲染。DOM 约减少 92%；耗时是受系统负载影响的单次样本，不将其作为 CI 固定时间阈值。

报告附件同时记录 CDP `JSHeapUsedSize` 和 `Nodes`，但这些指标会受 GC、同一渲染进程及前序页面影响，不等同于当前页面独占内存或浏览器进程 RSS。没有据此宣称内存泄漏已解决。DOM 表使用当前文档实际元素数。

## 行为与边界

- 保留账号列表和模型列表已有的虚拟化。
- 密钥的分组折叠状态和批量选择由列表父层持有；滚动卸载分组不会丢失批量选择。
- 小列表、关联凭据定位和引导导入保留直接渲染路径，便于现有定位／聚焦流程访问目标 DOM。
- 验证滚动到第 100 个账号、返回后保留选择、搜索无结果及恢复、全部折叠；搜索触发原有服务端重新加载及选择有效性校验。
- 验证并检查 390px／320px 截图。
- 本次按账号分组虚拟化，并未进一步虚拟化单个账号内部的大量密钥。关联定位／引导路径也仍可能挂载完整列表。
- 全账号密钥数据加载和服务端搜索仍有明显耗时；保留现有加载调度、鉴权边界及站点兼容性，不将渲染优化描述为消除了所有加载延迟。
