# Application i18n Guidance

Use for translation keys, locale resources, or language behavior. For adding an entire language, use the project `add-app-language` skill.

## Keys and types

- Type explicitly passed translation functions as `TFunction` from `i18next`.
- Prefer literal keys or finite typed selections that the extractor can enumerate. Constrain runtime keys to an owned family and handle unknown values; never pass raw user/backend text to `t`.
- Keep UI copy in locale resources and update affected keys across supported app locales. Use `defaultValue` only for intentional missing-key contracts, not to conceal missing translations.
- Keep locale key shapes aligned. When changing copy for an action or workflow, inspect the same keys in sibling locales; disclose any explicitly out-of-scope or generated locale.

## Plurals

- Use `t(key, { count })` and locale-owned plural forms when the number participates in the phrase's grammar. Keep numbers separate only for genuinely independent visual metrics.
- Unexpected plural rewrites require correcting source intent, not blindly patching locale JSON. Preserve interpolation and markup.

## Extraction and validation

- Preserve unenumerable runtime key families narrowly through extractor configuration or a plugin, not dummy calls, unreachable code, or extraction-only comments. Prefer extractable `t("ns:key")` calls unless a wrapper is configured.
- Key, translation-call, or locale changes require extraction-integrity evidence; locale-resource changes also require completeness evidence. Reuse an imminent pre-commit hook's extraction/status checks; otherwise run `pnpm run i18n:extract:ci` and, when relevant, `pnpm run i18n:status`.
- After extraction or any file-changing hook, inspect the affected locale diff against the task base, including removed keys and plural rewrites. A clean extraction check does not prove earlier deletions were intended or translations are good.
- If extraction removes needed keys, fix source usage or extractor configuration instead of manually restoring JSON that will be removed again.
