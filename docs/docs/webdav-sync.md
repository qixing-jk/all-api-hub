# 云端备份与自动同步

> 在一个同步服务中选择 WebDAV 或 GitHub Secret Gist，定期备份共享数据，实现多设备同步与灾备。

## 功能亮点

- **一键备份/还原**：在「导入导出」页面选择同步服务后，可随时上传或下载 JSON 备份。
- **自动同步**：后台定时同步（默认 1 小时），根据策略自动合并或覆盖数据。
- **多策略支持**：可选择“合并 / 仅上传 / 仅下载”，满足主次设备差异化需求。
- **冲突合并**：合并模式下按更新时间保留较新的账号、书签与偏好；删除账号或书签时会记录删除标记，避免旧备份在下次同步后把它们重新带回。
- **安全写入**：上传备份时会先写入同目录临时文件，读回校验后再移动到正式备份文件，降低上传中断造成远端备份损坏的风险；若坚果云在目标文件已存在时对 `MOVE` 返回 409，扩展会先删除正式备份再重试移动。
- **GitHub Secret Gist**：可使用 GitHub Token 连接已有 Secret Gist，或创建新的不公开列出的 Gist。Gist 上传始终使用加密备份。

## 前置条件

1. 准备可访问的 WebDAV 服务端：如 Nextcloud、坚果云、Alist WebDAV、NAS 等。
2. 获取 `URL / 用户名 / 密码`，确保具备读写权限。
3. 若需自动同步，建议让浏览器常驻后台（桌面 Chrome/Edge 或移动端 Kiwi）。

## 配置入口

1. 打开扩展 → **导入导出** → 「云端同步」设置。
2. 在「同步服务」中选择 WebDAV 或 GitHub Secret Gist。
3. WebDAV 填写：
   - **服务器地址**：可指向目录或具体 JSON 文件；若填目录将自动在其下创建 `all-api-hub-backup/all-api-hub-1-0.json`。
   - **用户名/密码**：用于 Basic Auth。
4. 点击 **“测试连接”** 验证配置无误，随后可执行“上传备份”或“下载备份”。

### GitHub Secret Gist

1. 在 GitHub 创建一个 Personal Access Token。建议使用 fine-grained Token，并只授予 **Gists: Read and write**；classic Token 只需要 `gist` scope。Token 只保存在当前浏览器，不会进入备份。
2. 选择 **GitHub Secret Gist**，填写 Token。已有 Gist 可填写其 ID 或 `https://gist.github.com/...` 链接；首次使用可留空。
3. 设置加密密码后点击 **“创建并上传 Secret Gist”**。扩展会创建 `public: false` 的不公开列出 Gist，并在 `all-api-hub-backup.json` 文件中保存加密内容。
4. 连接已有 Gist 时先点击 **“测试连接”**。如果 Gist 是公开的、被删除、没有该文件或文件内容损坏，扩展会停止操作，不会把本地数据清空。

Secret Gist 只是“不公开列出”的链接，不是访问控制或权限隔离。请同时保护 Token、加密密码和 Gist 链接；不要把 Token 写入备份或截图。GitHub Gist 的 Token、Gist ID/链接和加密密码不会进入手动 JSON 导出；迁移到新设备后需要重新配置 Gist。现有 WebDAV 用户的手动导出行为保持不变。

## 自动同步

在同一页面启用 “自动同步” 可后台定时同步当前选中的同步服务：

| 选项 | 说明 |
|------|------|
| **开启自动同步** | 对应 `webdav.autoSync` 开关，关闭后仅保留手动备份。WebDAV 与 Gist 共用同一套自动同步设置，但同一时间只有当前选中的服务会运行。 |
| **同步间隔** | 以秒为单位，默认 3600 秒（1 小时）。 |
| **同步策略** | `merge`（合并）、`upload_only`（以本地覆盖远程）、`download_only`（以远程覆盖本地）。 |
| **立即同步** | 触发 `webdavAutoSync:syncNow`，便于调试；若正在同步会提示稍后再试。 |

### 调度流程

1. 用户保存设置后，`webdavAutoSyncService.setupAutoSync()` 会按当前服务重新创建浏览器 Alarms 调度；Gist 的最小间隔为 5 分钟，以减少 GitHub API 请求。
2. 执行同步时：
   - 先调用当前同步服务的连接测试确认凭据有效。
   - 下载远程备份（若不存在则视为首次备份）。
   - 导出本地账号与偏好，依据策略决定最终数据：
     - **合并**：根据 `updated_at` / `lastUpdated` 时间戳保留最新项；账号与书签的删除标记会随同步参与合并，防止已删除条目被旧远程副本恢复。账号冲突采用“整个账号最后写入者胜出”（whole-account LWW），不会逐字段合并，因此较新的账号会连同其签到配置一起替换较旧账号。
     - **仅上传/下载**：直接选取本地或远程数据。
   - 将合并结果写回本地（通过 `accountStorage.importData` + `userPreferences.importPreferences`）。
   - 生成新的 JSON 后上传到当前同步服务。WebDAV 会使用临时文件读回校验后再替换正式文件；Gist 会带上上次读取到的 revision，并在上传后重新读取校验内容。
3. 同步状态（成功/失败、最后执行时间）会通过 `WEBDAV_AUTO_SYNC_UPDATE` 消息广播，可在前端监听或查看控制台日志。

### 版本兼容与多设备升级

当前版本写出的备份格式为 V4，并会把旧 V6 账号的签到配置升级为 V7。V1–V3 备份仍可导入；上一版 V3 读取器遇到 V4 时会尽力拒绝导入，避免按旧结构覆盖数据，但更早、对未知版本采取宽松解析的客户端不保证安全。

请先暂停自动同步，再把共享同一云端备份的设备全部升级到支持 V7 账号的版本，最后重新启用同步。不支持 V6 与 V7 客户端同时写入同一个备份；并发写入时，whole-account LWW 可能让旧客户端用 V6 账号覆盖 V7 签到配置。Gist 更新会检查读取时的 revision；如果另一台设备先写入，会报告冲突并保留本地数据，稍后重新同步。若必须回退旧版，请先停用其他设备的同步，并保留独立备份文件。

## 自动签到与多设备

账号和偏好设置可以随 WebDAV 同步，但自动签到的**当天执行状态、最近结果和浏览器闹钟不会跨设备共享**。多台设备同时开启每日计划时，仍可能重复签到；如需避免，建议只在一台设备上开启自动签到计划。

## 安全建议

- 建议在 WebDAV 端为备份目录单独创建子账号或访问令牌；GitHub Token 只授予 Gists 所需的最低权限。
- 勿在公共设备上保存 WebDAV 密码，必要时定期更换。
- 若同步失败提示 401/403，请确认服务器支持 Basic Auth 并允许 `MKCOL/PUT/GET` 方法。

## 常见问题

| 问题 | 处理方式 |
|------|----------|
| 测试连接失败 | 检查 URL 是否包含协议（https://），以及是否允许远程写入。 |
| 自动同步无反应 | 可能因浏览器被系统休眠或未启用自动同步；重新打开扩展并保存设置。 |
| 合并后出现重复账号或书签 | 手动删除重复项并重新上传；如需严格控制，请使用 “仅上传” 策略。已删除的账号和书签会通过删除标记参与后续合并，通常不会被旧备份重新恢复。 |
| 上传前提示远端备份损坏 | 表示现有 WebDAV 备份不是有效 JSON。确认本设备数据完整后，可以按提示用当前设备的全部共享数据重建远端备份；若本设备数据不完整，请先从数据完整的设备上传或导入完整备份。 |
| Gist 提示内容为空、损坏或格式不兼容 | 扩展会停止本次上传/导入，不会将其当成空备份，也不会清空本地数据。先在 GitHub 检查 `all-api-hub-backup.json`，确认加密密码和 Gist 内容后再重试。 |
| Gist 返回 401/403/404 或限流 | 401 检查 Token 是否过期；403 检查 Gists 权限；404 检查 Gist ID 或是否已删除；限流请等待提示时间后再试。 |
| 坚果云覆盖上传时出现 409 | 坚果云可能在正式备份文件已存在时对带 `Overwrite: T` 的 `MOVE` 返回 409。扩展会自动删除目标文件并重试移动，通常无需手动处理。 |
| JSON 文件过大 | 建议定期清理已失效账号或分批导出，避免超出 WebDAV 限制。 |
