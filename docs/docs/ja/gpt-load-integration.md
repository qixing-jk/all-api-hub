# gpt-load

[gpt-load](https://github.com/tbphp/gpt-load) は All API Hub の管理サイト機能に対応しています。接続を一度設定すれば、拡張機能からゲートウェイのグループ（チャンネル）を表示・作成・編集・削除でき、アカウントキーや API 資格情報をインポートしたり、各グループのキープールとモデルリストを直接編集したりできます。

gpt-load はセルフホストの AI ゲートウェイ（Go 製）で、それ自体に上流アカウントの意味（残高・プラン・チェックイン）はありません。**管理サイト**としてのみ接続でき、アカウントリストには表示されません。

## 接続設定

1. **設定 → 基本設定 → セルフホスト型サイト管理** を開き、サイトタイプを **gpt-load** に切り替えます。
2. **ゲートウェイアドレス** を入力します：ブラウザで gpt-load ダッシュボードを開くときに使う URL（例：`http://localhost:3001`）。
3. **管理キー** を入力します：ゲートウェイのルート `AUTH_KEY`（`AUTH_KEY` 環境変数、または生成された `data/auth.key` ファイル）。
4. **接続を確認** をクリックします。ゲートウェイに到達でき、キーが受け入れられることを確認します。

gpt-load は Bearer のみで Cookie セッションに依存しないため、拡張機能は一時ウィンドウや同一オリジンアクセスを必要としません。ブラウザから到達できる限り、リモート展開にもそのまま使えます。

### キーとロックアウトについて

管理キーはゲートウェイ上のすべてのチャンネルキーと同等の権限を持つため、信頼できる環境でのみ保存してください。ゲートウェイは送信元 IP ごとに失敗を制限します：**30 分間に 5 回失敗すると 30 分間ロックされます**。検証前にはキーが正しいことを確認し、失敗後に何度も再試行しないでください。

## チャンネル管理

**チャンネル** ページで gpt-load を選択すると、検索・詳細表示・新規作成・編集・削除ができます。

gpt-load のチャンネルは**グループ**です：ひとつのチャンネルドライバ（35 種内蔵：`openai`、`anthropic`、`gemini`、`deepseek`、`openai_compatible` など）、チャンネルパラメータ（最低 `base_url`）、資格情報プール、モデルリストで構成されます。

| フィールド | 説明 |
| --- | --- |
| 名前 | ゲートウェイ上のグループ名 |
| タイプ | ゲートウェイ内蔵のチャンネルドライバ ID（一覧はゲートウェイからリアルタイムに読み込み） |
| アドレス | チャンネルレベルの上流 `base_url`。既知のファーストパーティプロバイダでは空欄にしてドライバの既定エンドポイントを使います |
| キー | グループの資格情報プール。ゲートウェイ標準のマルチキー対応 |
| モデル | グループのモデルリスト。グループ単位で保存され、まとめて置き換えます |
| 料金倍率 | チャンネルの報告コストに適用する倍率（残高・レート制限の集計用） |
| 重み | 手動ロードバランスの重み。大きいほど割り当てられるトラフィックが増えます |

**作成**：ドライバを選び（このゲートウェイが提供するドライバは **ロード** ボタンで読み込み）、アドレスとキーを入力し、モデルを選択します。キーごとにプールの 1 行になります。

**編集**：名前・有効状態・アドレス・モデル・倍率・重みを編集できます。チャンネルドライバは作成後に変更できません（別ドライバへの付け替えは、現在のドライバに紐づいたプールを消去するため）、読み取り専用で表示します。モデルリストは `PUT /api/groups/:id/models` でまとめて置き換えます。

**キープール**：ゲートウェイの資格情報リストは常にマスクされた値のみを返し、拡張機能も一覧・詳細ではマスク済みデータだけを使います。平文は明示的な操作（マッチング・移行など）でのみ 1 行ずつ読み取ります。新しい行はゲートウェイの `POST /credentials/import` で一括インポートし、削除行は `DELETE /credentials/:id` を呼び、既存キーの置換は「新しい値をインポートして古い行を削除」の形になります。

**チャンネル移行**：gpt-load は移行元にも移行先にもなれます。移行元ではキープール全体を読み取り（マルチキーもまとめて移行）、移行先では 1 回の作成でグループのプールへ全キーを書き込みます。ドライバはプロトコル系統でマッピングされます（openai、anthropic、gemini、deepseek など）。ルート表にないドライバ（grok、cerebras など）は移行元にできず、型が未対応と表示されます。

## アカウントキー / API 資格情報のインポート

1. **設定 → 管理サイト** で gpt-load を選択・設定します。
2. **キー管理** または **API 資格情報ライブラリ** を開き、行の管理サイトインポート操作をクリックします。
3. ダイアログで名前・ドライバ・アドレス・キー・モデルを確認し、送信します。

インポートのプリフィル規則：

- 既知のファーストパーティプロバイダエンドポイント（例：`https://api.deepseek.com`）は該当ドライバを選択し、アドレスは**上書きしません**。
- その他のアドレスは `openai_compatible` ドライバを選択し、送信元アドレスを `base_url` オーバーライドとして書き込みます。
- 送信元が宣言するモデルはグループのモデルリストに引き継がれます。

インポートは常に単一の作成ルート（`POST /api/groups`）を使います。ゲートウェイは到達性を検証しないため、インポートの成否はゲートウェイの外部接続に依存しません。資格情報の有効性の検証は拡張機能自身が行います。

## 対象外

- **バッチモデル自動同期**：グループのモデルリストはエディタから書き込めますが、バックグラウンドのバッチモデル同期タスクは登録していません。一括更新はゲートウェイのパネルで行ってください。
- **サブスクリプションチャンネル**：gpt-load は Claude/Gemini などのサブスクリプションアカウントを資格情報として紐づけられます（ブラウザ OAuth フロー）。本統合は当面 `api_key` グループのみ対応します。
- **ゲートウェイのアクセスキーワークスペース**：下流の `sk-gl-` キーはゲートウェイの **Access Keys** ページで管理します。

## よくある質問

- **キーが拒否される（401/423）場合は？** 正しい `AUTH_KEY` を使ってください。短時間に何度も失敗すると 30 分間ロックされます。ロック中はゲートウェイで設定を確認してください。
- **名前の競合は？** ゲートウェイは同名グループを拒否します。名前を変更するか、先にゲートウェイパネルで同名グループを削除してください。
- **インポート後にモデルリストが空？** グループのモデルリストはグループ単位で管理されます。エディタでモデルを選択して保存するか、ゲートウェイパネルで設定してください。
- **送信後に結果が不確実？** ゲートウェイが 5xx を返した場合、書き込みが適用されたか不明です。先に一覧を更新して確認し、再試行するか判断してください。
