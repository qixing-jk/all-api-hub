# gpt-load 管理

[gpt-load](https://github.com/tbphp/gpt-load) 已接入 All API Hub 的管理站点功能。配置一次连接后，即可在插件中查看、创建、编辑和删除网关的分组（渠道），也可以从账号密钥或 API 凭据库导入，并在插件里直接维护分组的多条密钥与模型清单。

gpt-load 是自建 AI 网关（Go 编写），本身没有账号语义（余额、套餐、签到）。它只能作为**管理站点**接入，不会出现在账号列表里。

## 配置连接

1. 打开 **设置 → 基础设置 → 自建站点管理**，将站点类型切换为 **gpt-load**。
2. 填写 **网关地址**：你在浏览器里打开 gpt-load 面板时用的地址，例如 `http://localhost:3001`。
3. 填写 **管理密钥**：网关的根管理密钥 `AUTH_KEY`（`AUTH_KEY` 环境变量，或数据目录下自动生成的 `auth.key` 内容）。
4. 点击 **验证连接**。验证通过后即可进入 **渠道管理**。

gpt-load 全程使用 Bearer 密钥，不依赖 Cookie 会话，所以插件不需要临时窗口，也不需要同源访问。远程部署同样可直接使用，只要浏览器能访问该地址。

### 关于密钥与锁定

管理密钥等同于整个网关上全部渠道的密钥，请在可信环境保存。网关对同一来源 IP 的失败尝试做限流：**30 分钟内失败 5 次会锁定 30 分钟**。因此验证配置前请先确认密钥正确，不要在连接失败后反复点击验证。

## 管理渠道

在 **渠道管理** 页面选择 gpt-load 后，可以搜索、查看详情、新建、编辑和删除渠道。

gpt-load 的管理对象是**分组（group）**：一个分组绑定一个渠道驱动（channel，内置 35 种：openai、anthropic、gemini、deepseek、openai_compatible 等）、一组渠道参数（至少含 `base_url`）、一个密钥池和一份模型清单。渠道字段：

| 字段 | 说明 |
| --- | --- |
| 名称 | 网关侧的分组名称 |
| 类型 | 网关内置的渠道驱动 id，例如 `openai_compatible`、（`type` 渠道驱动由网关下发，创建时可从网关实时读取列表） |
| 地址 | 渠道级的上游地址（`base_url`）。已知一手提供商的地址可留空，由网关使用驱动自带的端点 |
| 密钥 | 该分组的密钥池。网关天然支持一个分组挂多条密钥 |
| 模型 | 该分组可用的模型清单，网关按分组保存，可整体替换 |
| 计费倍率 | 对渠道上报成本做倍率核算（余额与限速统计用） |
| 权重 | 手动负载均衡权重；越大分到的流量比例越高 |

**创建渠道**：选择渠道驱动（必要时点击“加载”从网关读取该实例实际支持的驱动）、填写地址与密钥、按需勾选模型。多条密钥对应密钥池的多行；导入后每组密钥形成一行。

**编辑渠道**：分组名称、启用状态、地址、模型、倍率与权重可直接修改。渠道驱动在创建后不可更换（重挂其他驱动会清空网关绑定到当前驱动的密钥池），只读显示。模型列表通过 `PUT /api/groups/:id/models` 整体替换。

**密钥池**：网关的密钥列表永远只返回打码后的值，插件在列表与详情中也只使用打码数据。需要明文时，只在明确操作（如迁移/比对）时按条取回。新增行会走网关的 `POST /credentials/import` 批量导入；删除行调用 `DELETE /credentials/:id`；替换某条已存密钥等于“导入新值后删除旧行”。

**渠道迁移**：gpt-load 既可作迁移来源，也可作迁移目标。作来源时会读取整个密钥池（多 Key 一并迁出）；作目标时按分组的密钥池一次性写入多条密钥。渠道驱动按协议族映射（openai、anthropic、gemini、deepseek 等）；网关内置但未纳入映射表的驱动（如 grok、cerebras）不能作为迁移来源，会提示类型不受支持。

## 导入账号密钥或 API 凭据

1. 在 **设置 → 管理站点** 中选中并配置 gpt-load。
2. 进入 **密钥管理** 或 **API 凭据库**，点击条目操作区中的管理站点导入按钮。
3. 在导入弹窗中确认名称、渠道驱动、地址、密钥和模型，然后提交。

导入的预填规则：

- 来源地址命中已知的一手提供商端点（例如 `https://api.deepseek.com`）时，预选对应渠道驱动，并**不再覆盖地址**。
- 其他地址一律预选 `openai_compatible` 渠道驱动，并把来源地址写成 `base_url` 覆盖。
- 来源声明的模型会带入分组模型清单。

导入一律走单条创建接口（`POST /api/groups`），网关不校验凭据可达性，因此导入成败不受网关出网能力影响；源凭据有效性仍由插件自己的验证流程判断。

## 做不到的事

- **批量模型自动同步**：分组模型可经编辑界面写入，但本集成未注册后台的批量模型同步任务；如需批量更新，到网关面板操作。
- **订阅型（subscription）渠道**：gpt-load 支持把 Claude/Gemini 等订阅账号作为凭据接入（需要浏览器 OAuth 流程），本集成首期只支持 `api_key` 连接类型的分组。
- **网关访问密钥（access key）工作区**：网关发给下游客户端（`sk-gl-`）的密钥在面板的 **Access Keys** 页面管理，插件不管理它们。

## 常见问题

- **提示密钥被拒绝（401/423）？** 换用网关正确的 `AUTH_KEY`。短时间多次失败会被锁定 30 分钟，期间请在网关确认配置。
- **提示名称冲突？** 网关不接受同名分组。换个名称，或先到网关面板删除同名分组。
- **导入后模型列表为空？** 分组模型清单由网关按分组维护；可在编辑界面勾选模型后保存，或到网关面板配置。
- **提交后提示结果不确定？** 网关返回了 5xx，写操作是否生效未知。先刷新列表核对，再决定是否重试。
