安装渠道与更新说明

All API Hub 有三类常见安装方式：浏览器商店版、GitHub 自更新版（Chromium .crx） 和 GitHub 手动安装版（解压加载）。如果你不确定该选哪个，优先使用浏览器商店版。

简单结论

Chrome、Edge、Firefox 用户优先安装对应商店版。商店版安装最简单，也不需要任何策略配置。

只有在用不了商店版（商店还没上架、浏览器装不了商店版或 Chrome Web Store 兼容版本）而必须走 GitHub 附件时，Chromium 浏览器才需要区分附件形式：

  • 推荐 .crx 自更新版：它和商店版一样由浏览器按发布页的更新清单自动更新，装一次之后不用再手动换包。stock Chrome / Edge 需要按文档配置一次扩展白名单策略（Linux 无需配置）。
  • .zip 解压加载版：不会自动更新，每次升级都要重新下载并重新加载，仅在 .crx 装不上时使用。

我该安装哪个版本？

你的情况建议选择更新方式
使用 ChromeChrome Web Store 版本浏览器自动更新，也可以在插件内手动检查
使用 EdgeEdge Add-ons 版本浏览器自动更新，也可以在插件内手动检查
使用 FirefoxFirefox Add-ons 版本Firefox 自动更新，也可以在插件内检查 AMO 已发布版本
使用 Brave / Vivaldi / Opera，且能用 Chrome Web StoreChrome Web Store 版本浏览器 / 商店机制自动更新
使用 Brave / Vivaldi / Opera，商店装不了先试 GitHub Release 中的 .crx 自更新版，装不上再用解压加载 .zip.crx 自动更新；解压加载版需重新下载
使用 QQ / 360 / 猎豹等浏览器浏览器内置扩展中心若可用则优先使用；否则先试 .crx 自更新版，再否则解压加载 .zip.crx 自动更新；解压加载版需重新下载
商店版还没收到某个紧急修复临时使用 GitHub Stable安装 .crx 可自动更新；解压加载版需手动下载
想提前体验开发中的功能Nightly / 开发版可能不稳定，只建议测试使用；Chromium .crx 同样自带自动更新

如果你使用 QQ、360、猎豹、Brave、Vivaldi、Opera 等浏览器，请查看 其他浏览器安装指南。其中 Brave、Vivaldi、Opera 通常可以先尝试 Chrome Web Store；需要手动安装时优先选 .crx，详见 Chromium 自更新安装。

我的浏览器算 Chromium 吗？

默认按 Chromium 处理：除 Firefox 和 Safari 外，常见的桌面扩展浏览器基本都是 Chromium 系。不确定时对照 浏览器表格。

为什么 GitHub 有新版，商店还没更新？

这是正常现象。项目通常会先把新版本发布到 GitHub，然后再提交到各浏览器商店。商店还需要审核和推送，所以可能会晚一些。

常见原因包括：

  • 商店还在审核新版本。
  • 商店已经通过审核，但还没有推送到你的浏览器。
  • 你的浏览器还没来得及检查扩展更新。
  • 公司电脑、浏览器策略或网络环境限制了扩展更新。

如果你用的是商店版，通常等浏览器自动更新即可。急需某个修复时，可以先看下方的手动检查方法。

在插件里检查更新

打开 All API Hub 设置页，在版本与更新区域点击 “检查更新”。未检查时只显示当前版本；想了解版本变化，可以直接点击 “查看更新日志”。

插件根据当前发行包的渠道选择检查方式：Firefox Add-ons 版检查 AMO 已发布的版本，GitHub 正式版检查最新正式发布，Nightly 按构建提交比较，避免版本号相同而漏报。Chrome 和 Edge 商店版还会查询浏览器是否已准备好更新。旧版或未标记的发行包仍可手动检查，是否支持自动检查取决于安装环境。

你可能会看到这些结果：

  • 已是最新版本：不用处理，可以查看更新日志了解版本变化。
  • 发现新版本：点击 “下载更新” 前往对应的发布页或 Firefox Add-ons 商店。AMO 已发布新版不代表 Firefox 已经下载完成。
  • 等待商店推送更新：商店版由浏览器自动更新，请等待商店推送。
  • 更新已就绪：浏览器已准备好更新，点击重载更新按钮即可应用。
  • 检查更新失败：可能是网络、GitHub / AMO 访问或浏览器更新检查暂时不可用，请重新检查。

注意

插件内检查不能跳过浏览器商店审核。如果 GitHub 已经发布，但商店还没上架，插件也无法直接把商店版更新到那个版本。

在浏览器里手动检查商店更新

如果你使用 Chrome 或 Edge 商店版，也可以让浏览器主动检查一次扩展更新。

Chrome

  1. 在地址栏打开 chrome://extensions/。
  2. 打开右上角的 开发者模式。
  3. 点击页面上的 更新。
  4. 等待浏览器检查扩展更新。

Edge

  1. 在地址栏打开 edge://extensions/。
  2. 打开 开发人员模式。
  3. 点击页面上的 更新。
  4. 等待浏览器检查扩展更新。

这个方法只能更新到商店已经提供的版本。如果商店还在审核，新版本仍然不会出现。

Firefox

Firefox 通常会自动更新扩展。你也可以打开 about:addons，进入扩展管理页面，检查是否有可用更新。不同 Firefox 版本的按钮位置可能略有差异。

什么时候适合从 GitHub 安装？

GitHub 附件适合这些情况：

  • 商店版还没收到你急需的修复。
  • 当前浏览器没有可用的商店版，也无法使用 Chrome Web Store 等兼容商店入口。
  • 你需要帮忙确认某个新版本是否解决问题。

GitHub 附件有两种形式，更新方式完全不同：

  • .crx 自更新版（GitHub 附件推荐）：浏览器按发布页的 updates.xml 自动获取新版本，和商店版一样不需要你手动换包。stock Chrome / Edge 需要先配置扩展白名单策略（Linux 无需配置；Windows 版 Edge 还要求设备入域），详见 Chromium 自更新安装。
  • .zip 解压加载版：不会自动更新，每次升级都要重新下载并重新加载，仅在 .crx 装不上时使用。

也就是说，GitHub 附件里优先选 .crx；商店版仍是第一选择，不需要这些配置。

安装前请注意：

  • 从商店版切换到 GitHub 版本前，建议先导出备份数据。.crx、.zip 与商店版的扩展 ID 不同，数据不会自动迁移。
  • 不建议长期同时安装多个来源的 All API Hub，除非你明确是在测试。
  • Firefox 没有对应的 GitHub 自更新通道，*-firefox.zip 同样不会自动更新，请使用 Firefox Add-ons 商店版。

安装和更新步骤请查看 其他浏览器安装指南。

常见问题

我需要一直点“检查更新”吗？

不需要。商店版和 .crx 自更新版都由浏览器自动更新。只有你看到 GitHub 已经发布新版，想确认商店版是否已经可更新，或者想立刻应用 .crx 更新时，再手动检查即可。

插件内“检查更新”会自动下载 GitHub 安装包吗？

不会。它按当前发行渠道检查版本状态，可打开 Releases 或商店页面，但不会自动下载 GitHub 安装包；解压加载包需要手动下载并更新。

点击“重新加载完成更新”会丢数据吗？

不会。它只是让已经下载好的商店更新生效。账号、Key、设置等数据仍然保存在浏览器扩展存储里。

GitHub 已发布新版，但插件仍然提示商店没有更新，怎么办？

如果你使用商店版，先等待商店审核和推送。急需修复时，可以临时从 GitHub Stable 安装 .crx 自更新版；使用前建议先导出备份数据。

手动安装版怎么更新？

  • .crx 自更新版：浏览器会自动更新，也可以在 chrome://extensions/ 点「更新」立即检查。
  • .zip 解压加载版：重新下载新版安装包并加载新版扩展目录，具体步骤请看 其他浏览器安装指南。
