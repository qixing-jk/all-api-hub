アカウントの追加

このガイドでは、自動認識、手動入力、またはブックマークの取り込みを使って、AI サイトのアカウントを All API Hub に追加する方法を説明します。追加後の整理、並べ替え、一括操作については、アカウント管理を参照してください。

1. 自動認識（推奨）

最も簡単な追加方法です。まずブラウザで対象サイトにログインしてから、次の操作を行います。

  1. **「アカウントを追加」**をクリックします。
  2. サイト URL を入力します。
  3. **「自動認識」**をクリックします。
  4. 拡張機能がサイト種別と現在ログイン中のアカウントを識別し、必要な情報を自動入力します。
  5. 内容を確認してアカウントを保存します。

サイトで Cloudflare 認証が使われている場合、拡張機能は補助ウィンドウを開き、認証完了後に検出を続行します。自動認識に失敗した場合は、よくある質問でログイン状態、認証方法、サイト互換性を確認するか、以下の手動追加を使用してください。

自動認識でセキュリティ確認が必要な場合

自動認識でアクセストークンの入力を求められた場合、検出済みのアカウント情報は保持されます。

  • New API では、完全なトークンをお持ちの場合はそのまま貼り付けられます。ツールバーのポップアップで 「拡張機能でトークンを作成」 または 「サイトで取得」 を選ぶと、入力中のフォームがサイドパネルに引き継がれます。サイドパネルが利用できない場合や開けなかった場合は、通常のページで続行します。詳しい手順は 拡張機能で New API の管理用トークンを作成する を参照してください。
  • その他のサイト では、ツールバーのポップアップで 「サイドパネルで続行」 を選びます。サイドパネルが利用できない場合は 「通常のページで続行」 を選びます。その後、サイトを開いてトークンをコピーし、フォームに戻って貼り付けます。

2. 手動追加

必要な情報とその確認場所は、サイト種別によって異なります。以下では、サイト種別ごとに手動追加の方法を説明します。

サイト種別は任意です。選択しなくてもアカウントを保存できます。その場合、サイト種別は一旦 unknown として記録され、後の更新や認識で自動補完されることがあります。

クイックリンク：

  • New API
  • Sub2API
  • OpenRouter

2.1 New API

New API のカスタマイズ版によって、ページ構成、ボタン名、機能の場所が異なる場合があります。実際に利用しているサイトの画面を優先してください。

  1. New API サイトにログインします。

  2. ブラウザのツールバーにある All API Hub 拡張機能アイコンをクリックします。入力内容を見比べやすいように、サイドパネルで開くことを推奨します。

  3. **「アカウントを追加」**をクリックし、現在のサイトアドレスを使用するか、アドレスを手動入力します。

  4. **「手動追加」**をクリックします。

  5. 次の項目を入力します。項目名をクリックすると、それぞれの説明に移動できます。

    • サイト名
    • サイト種別
    • ユーザー名、ユーザー ID
    • Access Token

    サイト名：拡張機能内でアカウントを区別するための任意の名前です。

    サイト種別：new-api を選択します。

    5.1 ユーザー名とユーザー ID の確認方法

    New API サイトにログインし、「プロフィール」または「個人情報」ページを開きます。ユーザー名とユーザー ID はこのページで確認できます。

    5.2 Access Token の確認方法

    有効な Access Token の完全な値を保存済みの場合は、そのまま入力できます。

    フォームに作成ボタンが表示される場合は、拡張機能で管理用トークンを作成することもできます。

    以下の手順を選ぶ前に、実際のサイトのトークン画面とボタンを確認してください。バージョンは目安です。フォークや機能のバックポートにより、異なる手順を使うサイトもあります。

    新しい New API（v1.0.0-rc.41 以降）では、トークンは 「セキュリティ → Access Tokens」（通常は /security）にまとまっています。Create access token を選び、サイトの指示に従って権限と有効期限を指定し、認証を完了してください。完全なトークンは作成時に一度しか表示されないため、すぐにコピーして拡張機能の 「アクセストークン」 欄に貼り付けます。権限はダイアログに並んでいるものをすべて付与してください。権限が足りないトークンは、後で使用量・残高の取得や API キーの管理を行う際に 403 を返します。トークンはそれぞれ独立した項目で個別に取り消せます。新しく作成しても、他のトークンは無効になりません。

    Generate / Regenerate ボタンのみのサイト（通常は rc.40 以前）

    旧バージョンでは、次の画像のようにプロフィールページ下部の「セキュリティ」欄にトークンが 1 つだけあります。Generate で作成し、すでにある場合は Regenerate になります。再生成すると古い Access Token は無効になるため、古いトークンを使う他のツールも更新してください。

    ここではアカウント管理用の Access Token を使用します。「トークン管理」の API キーはモデルの呼び出しに使用します。

  6. 0 より大きい チャージ金額レート（CNY/USD）を入力して、アカウントを保存します。実際に利用するサイトでチャージレートを確認し、そのサイトで使われている値を入力してください。

入力時の推奨設定

Access Token 認証を優先してください。保存後にアカウントを更新できない場合は、まずサイト種別、ユーザー ID、Access Token が正しいか確認します。対象サイトで明示的に必要な場合にのみ Cookie 認証を試してください。

アカウント情報を保護してください

Access Token と Cookie は機密情報です。完全な内容を他人と共有したり、公開スクリーンショットや問題報告に含めたりしないでください。

拡張機能で New API の管理用トークンを作成する

自動認識で New API のアカウントが見つかり、アクセストークンの追加を求められたら、**「拡張機能でトークンを作成」**を選択します。権限を指定して管理用トークンを発行できるサイトであれば、サイト側のトークン管理ページが使えない場合でもこの方法を利用できます。AI 発財網では Linux DO を使って、トークンの作成からアカウントの保存まで確認済みです。

  1. トークンの権限と有効期限を選び、**「確認してトークンを作成」**をクリックします。サイトが提示する方法で本人確認を完了します。
  2. 拡張機能がトークンを検証し、アカウントのフォームに入力します。内容を確認して **「アカウントを保存」**をクリックします。

トークンが有効で必要な権限があれば、サイトからログアウトした後も拡張機能でアカウント情報を更新できます。すでにトークン全体が手元にあれば、そのまま貼り付けられます。**「サイトで取得」**を選び、サイトでコピーまたは作成したトークンを貼り付ける方法もあります。

2.2 Sub2API

Sub2API サイトによって、ページ構成、ボタン名、機能の場所が異なる場合があります。実際に利用しているサイトの画面を優先してください。 Sub2API の Access Token はブラウザの Local Storage に保存され、ログイントークンには有効期限があります。自動認識（第 1 節）の使用を推奨します。手動で追加する場合は、以下の手順に従ってください。

  1. Sub2API サイトにログインします。

  2. ブラウザのツールバーにある All API Hub 拡張機能アイコンをクリックします。入力内容を見比べやすいように、サイドパネルで開くことを推奨します。

  3. **「アカウントを追加」**をクリックし、現在のサイトアドレスを使用するか、アドレスを手動入力します。

  4. **「手動追加」**をクリックします。

  5. 次の項目を入力します。項目名をクリックすると、それぞれの説明に移動できます。

    • サイト名
    • サイト種別
    • ユーザー ID
    • Access Token

    サイト名：拡張機能内でアカウントを区別するための任意の名前です。

    サイト種別：sub2api を選択します。

    5.1 ユーザー ID の確認方法

    Sub2API のプロフィールページにはユーザー名とメールアドレスだけが表示され、数値のユーザー ID は直接表示されません。ブラウザの開発者ツールで確認してください。

    1. Sub2API サイトにログインしてから、F12 を押して開発者ツールを開きます。
    2. **Network（ネットワーク）**タブに切り替え、F5 を押してページを再読み込みします。
    3. リクエスト一覧から auth/me を見つけて開き、**Response（レスポンス）**を選択します。
    4. "data" 内の "id" フィールドを探します。この数値がユーザー ID です。

    別の方法：開発者ツールで Application（アプリケーション） → Local Storage → サイトのドメインを開き、auth_user を探します。その id フィールドもユーザー ID です。

    5.2 Access Token の確認方法

    Sub2API の Access Token はページに表示されず、ブラウザの Local Storage に保存されています。開発者ツールで取得してください。

    1. Sub2API サイトにログインしてから、F12 を押して開発者ツールを開きます。
    2. Application（アプリケーション） → Local Storage → サイトのドメインを開きます。
    3. auth_token を探し、通常 eyJ で始まる長い文字列をコピーします。これが Access Token です。

    このトークンはサイトへのログインに使用します。「API キー」ページでモデル呼び出しに使う API キーとは異なります。

    セッションの選び方

    セッション方式の既定値は ブラウザーセッション です。ウェブサイトのログイン状態を利用します。サイトのタブを閉じた後も、一時ウィンドウで再同期できます。ログインの期限が切れた場合、サイトの鍵が削除された場合、または別のアカウントに切り替えた場合は、サイトで対象のアカウントに再ログインしてください。

    同じサイトで複数のアカウントを使う場合や、サイトとは別にセッションを更新したい場合は、セッション方式で 独立バックグラウンドセッション を選びます。

    1. ユーザー ID を入力します。アカウントログインが未設定の場合は、ログインを設定 を選び、ログイン情報を入力します。
    2. アカウントログインの セッション取得 を選び、必要に応じてサイトの認証を完了します。独立したセッションを取得済み と表示されたら、アカウントを保存します。新しいセッションが必要な場合は、セッション方式の下にある 再ログイン を選びます。ログインを自動復旧 をオンにすると、セッションの期限が切れたときにもバックグラウンドで再ログインします。
    3. Refresh Token をすでに持っている場合は、Refresh Token を手動でインポートまたは貼り付け を開きます。対応サイトでは サイトから取り込む を選ぶか、トークンを貼り付けます。インポートしたセッションを複数のブラウザーやツールで使うと、更新に失敗することがあります。更新用の認証情報がブラウザーに紐付いているサイトでは、上のログイン方法を使うよう案内が表示されます。

    独立バックグラウンドセッションを選んだ場合は、更新用の認証情報を取得してから保存してください。この情報はバックアップやエクスポートにも含まれるため、ファイルは安全に保管してください。

  6. 0 より大きい チャージ金額レート（CNY/USD）を入力して、アカウントを保存します。

    自動認識では、まずサイトが返すチャージ換算設定を使用します。サイトから有効な値が得られない場合にのみ、既定値 7.2 にフォールバックします。実際のチャージレートに合わせて手動で調整することもできます。この値は画面上の残高換算にのみ使われ、アカウント機能には影響しません。

入力時の推奨設定

Sub2API は Access Token 認証のみをサポートし、Cookie モードには対応していません。トークンを読み取り、ユーザー ID を自動補完できる 自動認識を優先してください。保存後に更新できない場合は、まずサイト種別、ユーザー ID、Access Token が正しいか確認します。

アカウント情報を保護してください

Access Token は機密情報です。完全な内容を他人と共有したり、公開スクリーンショットや問題報告に含めたりしないでください。

2.3 OpenRouter

  1. OpenRouter にログインします。

  2. ブラウザのツールバーにある All API Hub 拡張機能アイコンをクリックします。入力内容を見比べやすいように、サイドパネルで開くことを推奨します。

  3. **「アカウントを追加」**をクリックし、現在のサイトアドレスを使用するか、アドレスを手動入力します。

  4. **「手動追加」**をクリックします。

  5. 次の項目を入力します。項目名をクリックすると、それぞれの説明に移動できます。

    • サイト名
    • サイト種別
    • Access Token

    サイト名：拡張機能内でアカウントを区別するための任意の名前です。

    サイト種別：openrouter を選択します。

    5.1 Access Token の確認方法

    OpenRouter のコンソールで **「Management Keys」**を開き、右上の **「+ New Key」**をクリックします。フォームに入力して **「Create」**をクリックし、新しい API キーをコピーして、All API Hub の **「OpenRouter 管理キー」**欄に入力します。

    キーの完全な内容は一度しか表示されません。紛失した場合は、新しいキーを作成して入力し直してください。

    クイックリンク：https://openrouter.ai/settings/management-keys

  6. 0 より大きい チャージ金額レート（CNY/USD）を入力して、アカウントを保存します。この値は USD 残高を CNY 表示に換算するために使われます。希望する換算レートを入力してください。OpenRouter のアカウントや請求には影響しません。

入力時の推奨設定

OpenRouter は常に **Management Key（Access Token）**で認証します。ユーザー ID は不要で、Cookie モードにも対応していません。保存後に更新できない場合は、OpenRouter の Management Keys ページで作成したキーか確認してください。既存キーの完全な内容は再表示できないため、新しく作成してすぐにコピーする必要があります。

アカウント情報を保護してください

Management Key は機密情報です。完全な内容を他人と共有したり、公開スクリーンショットや問題報告に含めたりしないでください。

2.4 Vercel AI Gateway

  1. Vercel コンソールにログインし、AI Gateway を利用するチームを開きます。
  2. 拡張機能で「アカウント追加 → 手動追加」を選び、URL に https://vercel.com、サイトタイプに vercel-ai-gateway を指定します。
  3. Vercel Tokens で対象チームにアクセスできるトークンを作成し、必要なメール認証を完了して、完全なトークンを拡張機能の「アクセストークン」に貼り付けます。モデル呼び出し用の AI Gateway API キーとは別の、Vercel アカウント用トークンです。
  4. チーム一覧の読み込み後、残高とキーを所有するチームを選択します。保存時にトークンのチームへのアクセス権が再確認されます。異なるチームは別々のアカウントとして保存できます。
  5. サイト名と正の換算レート（CNY/USD）を入力して保存します。残高は米ドルで取得され、レートは換算表示にのみ使用されます。トークンが失効した場合は、コンソールで再作成して保存済みの認証情報を更新してください。

トークンの保護

公開スクリーンショットやフィードバックに完全なトークンを含めないでください。Cookie はこのトークンの代わりにはならず、拡張機能はバックグラウンドで Vercel トークンを作成・更新しません。

3. Cookie モード

API の保護が厳しいサイトや大幅にカスタマイズされたサイトで Access Token モードが動作しない場合は、**「Cookie モード」**を試してください。このモードでは、拡張機能が現在のログインセッション（Cookie）を使ってデータを取得します。

Cookie には有効期限があり、すべてのサイトで使用できるわけではありません。まず自動認識と Access Token 認証を試し、対象サイトで明示的に必要な場合にのみ Cookie モードへ切り替えてください。

4. ブックマークからアカウントを一括取り込み

AI 中継サイトをブラウザのブックマークに保存している場合は、「ブックマークから取り込む」でスキャンし、複数のアカウント候補を作成できます。

  • 入口はアカウント管理ページ上部と、「アカウントを追加」ダイアログ内の「ブックマークからアカウントを取り込む」にあります。

  • ブックマークへのアクセスは任意権限です。ユーザーが許可した場合にのみ、拡張機能がブックマークを読み取れます。

  • 処理の流れ：

    権限を許可 → ブックマークツリーを読み取り → 範囲を選択 → スキャンして候補を作成 → プレビュー → 取り込み → 結果を集計

  • 既存のアカウントは既定でスキップされ、重複して取り込まれません。

  • 拡張機能はできるだけ自動でアカウントを追加します。一部のサイトでは、ログイン、認証、情報の補足が必要になる場合があります。

  • 結果は追加済み、未完了、スキップで集計されます。未選択の候補サイト（既定でスキップされる既存サイトを含む）はスキップに数えられます。

  • 追加済みのアカウントは保持されます。ログインやサイト認証を完了した後、「未完了の項目を再試行」を利用できます。この一括処理で追加済みの項目は再追加されません。

  • 「手動で完了」で通常のアカウント追加画面を開き、URL と検出済みのサイト種別・認証方式を引き継いで、サイトに合わせた設定を完了できます。

5. アカウント追加を効率化する

設定 → 基本設定 → アカウント管理で、次の項目を有効にするとアカウント追加を効率化できます。

  • ⚡ 現在のページ URL を自動入力：オンにすると、「アカウントを追加」をクリックした際に、現在のブラウザタブの URL が自動入力されます。
  • 🔑 アカウント追加後に既定のトークンを自動作成：アカウントの追加に成功すると、サイト側で既定の API キー（Token）の作成を試み、すぐにエクスポートできるようにします。
    • AIHubMix：AIHubMix の完全な API キーは作成時に一度だけ表示されます。新しい AIHubMix アカウントを追加した後（「Managed Site に設定」フローを除く）、拡張機能は既存のキーを確認します。キーがある場合は作成確認を表示しません。ない場合は、既定キーを作成するか確認し、一度だけ完全なキーを表示します。キャンセルした場合は、後でキー管理から作成し、完全なキーをすぐに保存してください。
  • ⚠️ 重複アカウント追加時に警告：同じ URL の既存サイトを追加しようとすると確認が表示されます。今回の追加を続行、キャンセル、または今後の重複警告を無効にして続行できます。

新しいプロファイルの既定値

アカウント設定が未構成の新しいプロファイルでは、既定値は次のとおりです。

  • URL の自動入力：オフ
  • アカウント追加後に既定のトークンを自動作成：オフ
  • 重複アカウント追加時に警告：オン
  • 並べ替えの優先順位：10 項目すべてオン

これは新しいプロファイルの既定値であり、設定変更後も固定される値ではありません。
