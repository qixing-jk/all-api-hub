# 账号密钥请求：减少重复读取的取舍

本记录提炼 2026-10-12 的审查及随后实施结果，原审查基线为 `abdfd5998`。范围是账号密钥管理，不包括管理站点 channel/provider CRUD。下列理由用于维护已有实现，不是尚待实施的缺陷清单。

## 根据写入语义决定读取

| 操作 | 需要保留的读取 | 可以复用的事实 |
| --- | --- | --- |
| 整体替换记录 | 为保留未编辑字段取得新鲜合并基线；LaoZhang 隐藏字段、Rix 方言不能用通用展示对象重建 | 完整且归属匹配的原生快照 |
| 局部 PATCH、单字段改名 | 按站点冲突策略决定；不能一律要求全量 inventory | 已接受的编辑快照、完整写响应或明确成功的字段增量 |
| 创建 | 响应不能提供资源身份时，可能需要创建前基线和创建后关联读 | 完整 POST 记录，或归属匹配的已有库存；空库存也是有效基线 |
| 相对资金转移 | 提交时读取新鲜来源余额，保留明确方向、金额及资金核验 | 同一操作内的身份与余额；不能用打开编辑器时的旧余额代替 |
| 多阶段写入 | 独立 expiry、分字段修改等需要保留部分成功语义 | 已明确成功的阶段，不能因后一步失败而重做前一步 |
| 不确定结果 | 用只读操作核验；读取失败不授权重新写入 | 已确认成功的事实和一次性 secret |

审查发现 New API 默认传输曾只返回 `true`，因此“适配器拿不到 id”不等于“服务端没有返回 id”。应先核实原生信封，保留可识别记录；缺身份时不能按同名随意选中，更不能重发创建。

## UI 更新与配置读取的边界

完整结果可用于更新同 scope 的已接受行，无须再打开会话、读取 workspace/groups 和整份 inventory。跨 scope、分页位置不明、只有一次性 secret 或无法关联资源时，仍需要明确的刷新策略。优化必须保留创建回调、路由交接、一次性 secret、旧异步结果拒绝和不确定状态恢复。

同一表单或会话已成功加载的 groups/channel 可复用；这不授权跨账号长期缓存，也不能把未知 group 当成无限制访问。余额刷新和用于操作的身份检查不能混用一个长期缓存。

维护入口：[公共提交边界](../../src/services/apiAdapters/accountKeyResources/collection.ts)、[编辑结果交付](../../src/features/KeyManagement/resources/workflows/useAccountKeyResourceEditorWorkflow.ts)。协议差异由各适配器拥有，不以站点类型跳过名单替代契约。

## 当时的真实验证边界

FoxCode 实测采用 POST 记录及成功 PATCH 结果，减少 inventory 读取；Cubence 验证 CRUD、quota/group/status 与重新打开；Dahl 验证实际分配、返还、取消、重新打开、命名同步与撤销，资金池和密钥总余额恢复。其他站点在这轮只有代码与行为测试依据，不能据此声称逐站原生实测。
