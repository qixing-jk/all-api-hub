# Daya：协议调查结论与维护线索

已合并：[PR #1735](https://github.com/qixing-jk/all-api-hub/pull/1735)。调查窗口：2026-10-20 至 2026-10-21，目标为 `https://api.dayaai.com`，最初观察到的站点版本为 `0.1.106`。这些是该窗口的协议与产品决策，不保证后续部署不变。

## 保留这些结论的原因

原调查中“目录价格尚未折扣”“模型目录未适配”“兑换入口隐藏所以不支持兑换”等早期判断，均被后续原生页面调查修正。以下保留最终结论及其依据，避免以后从旧笔记重新引入这些假设。

## 身份与站点边界

- `api.dayaai.com` 是已核验的控制台；原生公开设置将 `daya.to` 和 `api-us.dayaai.com` 列为推理地址。`dayaai.com` 的聊天产品虽然共享父域 Cookie 范围，但未核实账号等价性，不能据此添加控制台别名或跨域发送凭据。
- 账号认证核验了 `daya_sid` Cookie；原生客户端调查没有找到可用于完整账号流程的 PAT 或 refresh-token 契约。恢复入口保留为网站交互登录。“没有发现”不等于证明上游永远不存在这些方式。
- 与 Sub2API 相似的路径和密钥字段不足以证明适配族可以合并。Daya 的 Cookie 身份、分组路由顺序、目录作用域和推理地址有独立契约；只有逐项验证这些契约后，才能考虑进一步复用。

## 原生编辑器的语义取舍

原生创建表单、前端请求构造和一次性资源读回共同确定了这些决策：

- 官方默认路由有顺序，应与当前可选择分组求交集并保序；不能把 `group_ids` 当作无序集合。分组描述和倍率需要在选择前可见。
- 原生使用卡片选择和拖动排序；扩展同时保留键盘上下移动入口。目的是完成路由排序，不要求复刻原生鼠标交互。
- `allow_fast` 在创建时默认启用；编辑时缺字段也按启用解释。编辑需要保留没有被用户修改的最新设置，不能用打开对话框时的旧值覆盖并发改动。
- 创建过期时间使用整天数，编辑使用绝对时间；两者不能共用会丢失精度的转换。无限额度与有限 USD 额度也应分别表达。
- 可选高级区可以初始折叠，但需要配置摘要，并在折叠后保留草稿。这项布局选择只用于 Daya，不改变其他站点的默认行为。

实现入口：[密钥编辑器](../../src/services/apiAdapters/daya/keyEditor.ts)、[资源会话](../../src/services/apiAdapters/daya/keyResources.ts)、[原生密钥协议](../../src/services/apiService/daya/keys.ts)。

## 两项被后续证据纠正的结论

### 目录价格已经折扣

原生目录卡片使用 `input/output_price_per_million` 显示当前价格，再除以 `display_discount_multiplier` 得到划线原价。因此不能再次乘折扣。这是站点级目录，已发布的 token 费率按 `exact` 正常显示；该标记说明费率有明确来源，不表示任意密钥的最终账单。目录未包含完整的上下文、图像及个性化计费条件，也不能证明模型调用权限。纯图像行的零值占位不能解释成免费 token 价格。

对应：[目录适配](../../src/services/apiAdapters/daya/modelCatalog.ts)、[回归测试](../../tests/services/apiAdapters/daya/modelCatalog.test.ts)。

### 隐藏旧兑换入口不代表没有当前兑换流程

早期调查只发现旧 `/redeem` 表单；后续检查当前 `/purchase` 的 `PurchaseRedeemCard`，确认它使用 `/api/v1/code/apply`，`channel=purchase`、`ref=console-topup`，请求体与 `Idempotency-Key` 共用同一个 UUID，且提交前不调用预览。

扩展采用当前流程。不确定结果重试时，在同一运行中的适配器内保留相同兑换尝试的幂等键；不能改走旧兑换 POST 作为回退。并发、订阅、额度重置等权益不等于 USD 入账；推荐折扣还需要原生结算。交付状态未确认时应回到官网核查。

对应：[兑换传输](../../src/services/apiService/daya/redemption.ts)、[结果与幂等尝试归一化](../../src/services/apiAdapters/daya/redemption.ts)、[回归测试](../../tests/services/apiAdapters/daya/redemption.test.ts)。

## 后续工作需要补齐的样本

- 完整用量历史：调查账号没有真实请求记录，尚缺非空请求、费用和缓存字段样本；现有历史汇总接口也不等于原生逐请求详情页。
- 套餐：调查账号没有订阅，不能用空结果证明多分组套餐、独立重置和多订阅展示已被验证。购买和支付仍是单独的工作流。
- 兑换：成功分支来自原生客户端契约与测试；没有可消耗的有效测试码，不能声称现场成功入账。后续需要一次性测试码、交付状态及权益读回。
- 签到只处理每日签到；手机、微信、邮箱绑定任务涉及账号凭据，不随奖励接口一起自动领取。

原始响应、账号截图与验收流水继续留在本地，不属于此规格。
