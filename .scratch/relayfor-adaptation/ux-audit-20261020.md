# RelayFor 官网体验差异审计

Status: ready-for-agent

审计日期：2026-10-20。插件基线：`f1a3e09de`。范围：普通账户适配、密钥、模型与价格、签到及官网跳转；管理端不在本次范围。

**结论：当前不能通过“体验只能比官网更好”的验收。** 常规密钥编辑和生命周期流程已有改善，但仍有核心信息丢失、受保护操作缺失和导航错误。测试通过只证明已覆盖的行为，不代表官网体验对齐。

## 证据与限制

- 当天直接下载官网 `https://relayfor.xyz/console` HTML 及其引用的 [console.bundle.js](https://relayfor.xyz/assets/4a72b1332ff7f64663d888267d7d01619def510af181aa51eb512cf9436e596a/console.bundle.js)。HTTP 200；前端资产标识与前次密钥修正引用一致。下面的官网能力是当前公开前端确认的交互契约，不能冒充当前账户的成功写入。
- 原始 HTML、格式化 bundle、探测脚本和验证日志保存在本工作树本地排除的 `../relayfor-parity-audit/`，不提交。bundle 引用行号均指该格式化副本；再次下载或格式化可能改变行号。
- 当前工作树 Chromium 扩展 E2E 重新运行，检查实际构建并使用模拟的官网 API；检查并查看了 `key-editor.png` 和 `rotation-actions.png`。并非官网登录账户实测。
- 开发浏览器新开的官网页跳转至 `/auth/?mode=login`；此次身份探测未完成，已中止并关闭本次创建的页。其他来源会话未调查；这不证明没有可复用会话。没有进行官网资源写入、领取奖励或改动其他浏览器页。
- 尚无同一真实账户在官网与本工作树扩展上的完整任务对照，尤其是 TOTP、套餐、分组与多活动状态。以下具体映射问题可从现有代码和官方前端确认；实际账户触发情况另列为未验证。

## 差异与修正目标

P1 表示影响主要任务完成或关键事实；P2 表示缺少流程、反馈或恢复能力。它们是后续实现优先级，本次只审计。

| 优先级 / 用户任务 | 官网交互及证据 | 当前适配与判定 | 达标目标 |
| --- | --- | --- | --- |
| P1 查看真正可用余额和套餐 | `balanceAmounts` / `renderBalanceSummary`（bundle 14637 起）分别列永久、限时和有效有限额订阅余额；不限额权益单独说明；展示套餐到期和重置时间 | [accountData.ts](../../src/services/apiAdapters/relayfor/accountData.ts) 只返回 `user.quota`，无 `nativeBalance`、`subscription`。有 $1 永久余额、$2 限时额度时，插件余额只显示永久部分；不能把官网合计直接当作所有模型可用余额。**更差 / 缺失** | 保留来源、适用限制、有效期和不限额权益，复用现有余额与订阅展示；避免把不同适用范围的额度简单混成一个数 |
| P1 新建和轮换受 TOTP 保护的密钥 | `protectedUserRequest`（14364 起）处理 `totp_required`、`totp_invalid`，新建/轮换会读取安全策略并收集 6 位码（16974、17744 起） | [API](../../src/services/apiService/relayfor/index.ts) 只发送普通创建/轮换请求；[错误解码](../../src/services/apiService/relayfor/responseError.ts) 丢弃 `error.type`。无验证码交互或明确的验证恢复分支。**缺失**；开启保护的真实账户尚未实测 | 共享敏感操作验证流程保留业务错误类型，支持取消/错误码重输；只在明确拒绝后重试，不能把不确定的轮换响应当作可重放 |
| P1 判断模型能否使用以及价格条件 | `modelPricingRow`（11841 起）展示 `accessible/access_reason`、订阅权益、训练授权要求、提示词审计及风险请求审计费 | [modelPricing.ts](../../src/services/apiAdapters/relayfor/modelPricing.ts) 仅映射名称、价格和端点，丢掉上述访问和费用条件。展示在列表中不等于可调用。**更差** | 展示可用状态和不可用原因、授权条件与额外收费；有官方授权流程的动作须明确可达，不能将这些模型作为无条件可用 |
| P1 识别/切换模型分组与专用计费 | 官网支持 `model_groups/selected_group`，`PUT /api/user/model-group` 会影响后续请求；展示当前分组倍率和远程压缩按次费用（11893、11974、12061 起） | 站点定义声明分组不适用；模型适配返回 `groupAccess: not-applicable`、`supportsGroupFiltering: false`，没有分组选择、当前分组事实、`effective_compaction_price`。基础/长上下文价格已有映射。**部分适配** | 区分服务端分组选择与本地列表筛选，保留当前选择和计费条件；专用端点费用须独立呈现，不能用普通输入/输出价代替 |
| P1 查看密钥剩余额度、限制与耗尽原因 | `tokenRow/tokenBudgetSummary`（16769 起）直接展示额度、白名单、到期、RPM/并发，以及预算已用/剩余/预占/重置 | [accountKeyResource.ts](../../src/services/apiAdapters/relayfor/accountKeyResource.ts) 提供旧 `fields`，但没有 `displayFacts`；[卡片](../../src/features/KeyManagement/presentation/accountKeyResourcePresentation.ts) 从 `displayFacts` 读取原生展示事实。实际 E2E 行只见名称、状态、脱敏 Key 和动作，缺少这些摘要；`budget_usage` 连类型和映射都没有。**更差** | 先接通既有 `displayFacts`，正确表示跟随账户/不限额；补齐预算使用及恢复时间，常用事实直接可见，更多明细展开。不能以“编辑器里能改”替代日常可读 |
| P1 官网快捷跳转到指定任务 | 官网路由由 `location.hash` 选择，`#tokens/#models/#usage/#overview/#redeem`（8797–8836；HTML 导航） | [站点定义](../../src/services/accountSiteDefinitions/definitions.ts) 使用 `/console/tokens`、`/console/models`、`/console/checkin`，调用记录只到 `/console/`。这些路径未携带官网选择面板所需 hash；无自定义默认页时会落到概览。**更差**；重定向最终行为尚未登录态实测 | 对齐 `/console/#tokens`、`/console/#models`、`/console/#usage`；签到位于概览，需指向实际位置；逐一验证按钮最终面板而非 HTTP 200 |
| P2 判断今日签到、补签与多活动完成情况 | 官网按活动和日期区分今日签到、补签、已领取、未开放；结果区分额度、订阅和多项权益（13614 起） | [签到 provider](../../src/services/checkin/autoCheckin/providers/relayfor.ts) 将任何 `can_makeup` 也当作今日未签，无可领取日就当已签；一次只选首个可领取活动/日期，奖励仅取 `quota_awarded`。今日已领且仍有历史补签会被显示为未签；多活动是否由上层再次调用未验证。**部分适配 / 更差** | 今日状态与补签分开；明确多活动完成范围与补签次数选择，反馈完整权益；无领取资格不能自动等同已签到；自动补签应有可理解的策略 |
| P2 兑换额度 | HTML 有单码、订阅码、预付卡以及批量/剪贴板兑换；bundle 调用 `/api/user/redeem` 和 `/api/user/redeem/batch`（17865、17988 起） | spec 原称官网没有兑换入口/端点，与当天官网矛盾；能力注册无 `redemption`，`redeemPath: null`。**缺失** | 更正能力结论，先提供准确官网入口；实现时覆盖原生结果、部分成功与批量反馈，不能只宣称全站不支持 |
| P2 在插件内查看公告 | 官方 `loadSiteAnnouncement`（11079 起）调用 `/api/site/announcement` 并显示公告正文 | [fetchRelayForAnnouncement](../../src/services/apiService/relayfor/index.ts) 只有定义，没有消费者；[能力注册](../../src/services/apiAdapters/relayfor/index.ts) 无 `site.notice/site.announcements`。**缺失** | 接入共享公告来源、刷新与本地已读机制；不伪造官网已读确认 |
| P2 查看调用明细与分析 | 官网 `GET /api/user/logs`，支持分页/筛选、扣费明细和导出；`/api/user/insights` 提供分析（13437、17446、18742 起） | 适配只提供今日/累计摘要，没有 RelayFor 明细映射；现有用量历史同步针对 New API `/api/log/self`，不能据此宣称已经支持 RelayFor。**缺失** | 官网记录直达应先可用；原生记录归一化后复用分析/历史 UI，验证分页、完成时间和扣费拆解 |
| P2 异常概览与指标可用性 | 官网请求层拒绝缺失 `today` 的概览（6355 起），给出可重试错误 | [parsing.ts](../../src/services/apiService/relayfor/parsing.ts) 仅检查 `user.id/username`；[accountData.ts](../../src/services/apiAdapters/relayfor/accountData.ts) 将缺失今日字段填 0 且标 Complete，`quota` 也未验证。**更差** | 必需事实验证失败可恢复；合法但未提供的指标标 unavailable，不把未知渲染为真实零值 |

其他官网工作流也已纳入调查：私有模型别名、模型健康、独享会话、积分突发容量、福利商城、词元贷、账户资料/安全/计费偏好。这些在当前 RelayFor 能力注册中没有对应实现，属于**未适配**，不是“官网不支持”。它们涉及独立产品流程，应单独评估；不能用核心账户适配的完成状态隐去差距。邀请/返利本次未发现明确入口，仍不应把关键词搜索无结果当作完整后台不存在的证明。

## 已有改进及其边界

- 密钥表单已有按任务分区、预算折叠、金额转换、白名单及错误校验；实际 Chromium 编辑器截图已查看。相对官网完整长表单，常规任务更紧凑；键盘、窄屏和官网登录态任务步数比较仍未完成。
- 启用/禁用直接执行，有提交中状态；轮换独立确认，准备期间保持正确意图，取消不写入；一次性新 Key 可复制并刷新库存。本次 E2E 重跑确认这些路径。
- 普通 token/按次计费、缓存与长上下文规则已映射；不能据此声称整个原生模型工作流完整。
- 保留隐藏/未知设置、跨账户集中管理和创建后导出有实际价值，但不能抵消上述核心信息和操作的退步。
