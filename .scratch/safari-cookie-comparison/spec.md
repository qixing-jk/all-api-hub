# Safari isolated Cookie transport: scope and acceptance

Status: accepted by the user as a Safari enhancement with documented limitations, including normal Safari builds and release packaging. The original Chromium work and PR #1669 are outside this branch. Preserve optional Cookie/website authorization, isolated native requests, failure protection and existing ordinary browser-fetch behavior.

The delivery criterion is the demonstrated improvement with known failures and untested scenarios recorded. The user accepted the bounded native evidence and deferred the remaining matrix and shared Popup issue to follow-up work. The subsequent scope correction includes the native handler in the ordinary Safari release pipeline and removes the experiment flag. Acceptance does not turn untested scenarios into passing results.

The proposed capability is concurrent saved Cookie accounts A/B without sharing either account's session with ordinary Safari tab C. The Swift handler uses an ephemeral `URLSession` with Cookie storage, credential storage and caching disabled, explicit Cookie/Origin, redirect rejection, bounded messages and cancellation. JavaScript checks optional Cookie permission, nativeMessaging and actual URL access, performs a credential-free capability handshake, and rechecks before dispatch. The check-to-dispatch race remains unresolved. See [research](../../e2e/safariNativeCookie/authorization-research.md) and [reproduction instructions](../../e2e/safariNativeCookie/README.md).

## Normal Safari release integration, 2026-10-23

Ordinary Safari builds now select the native transport for explicitly saved account Cookies without an experiment flag. Safari declares `nativeMessaging`; Cookie and DNR stay optional, and Chromium/Firefox permission selection is unchanged. Missing website/Cookie permission returns the localized permission error; missing/old handlers receive only a credential-free capability handshake and fail closed. Private requests do not fall back to ambient browser sessions, temporary pages or DNR. The transport retains HTTPS scope restrictions, bounded text bodies/responses, redirect rejection, Cookie/credential storage exclusion, Set-Cookie suppression and cancellation.

`scripts/prepare-safari-release-assets.sh` and the independent validation converter share `scripts/configure-safari-native-cookie-project.py`, which embeds the Swift handler, aligns the containing app/extension bundle IDs and enables sandbox network access. Source installation instructions now include that step; Chinese, English and Japanese Safari guides are synchronized. Users installing the generated Xcode bundle need no separate native host program.

The actual normal pipeline commands were `pnpm run zip:safari`, `bash scripts/prepare-safari-release-assets.sh`, `xcodebuild -list -json`, `xcodebuild ... -configuration Release ... archive`, and `codesign --verify --deep --strict`. Only application identity was changed for the independent trial; no probe/HMR or experiment flag was used. The converter listed macOS and iOS schemes; only the macOS scheme was archived and tested. The archived extension's actual entitlements include outgoing network access. Environment versions are unchanged from the comparison above.
