# 快速创建签到适配 issue（切片 A）

Status: resolved

Parent spec: `../spec.md`，Part 1 为本票实现依据；Part 2 的扫描属于 02。

## Objective

用户无需抓包或完整证据，就能从已有签到相关界面创建预填的 GitHub issue。报告是申请辅助信息，不是协议验证的前置要求。

## Scope

- 首版同时覆盖 parent spec Part 1 的入口表：账号签到配置、账号操作菜单、自动签到执行结果、账号状态表，以及已有检测/刷新反馈的账号明细。不把结果页入口延后，不新增独立批量刷新页面。
- 所有入口共用反馈组件和报告生成器，只传账号及可选受控状态。未知/不支持使用“申请签到适配”，其他情况使用“反馈签到问题”；异常处就近展示，正常处保留次要/更多菜单入口。登记稳定 target id，窄屏复用已有菜单。
- 编辑中的账号使用当前表单站点信息，不先保存，不丢失未保存内容，改过站点地址时不混入旧部署证据；其他入口定位对应账号。已删除账号说明无法定位并返回账号列表。只有总数的汇总引导到账号列表，不合并多账号报告。
- 复用 Dialog：可选站点名称/现象、默认开启的附带地址开关、可编辑预览。
- 从当前账号逐项生成版本/平台、站点类型、可选 origin、有效探测结论与选择状态；复用 inspection，正确处理 `lastUnknownAttempt`、未探测与无候选。
- “创建 GitHub issue”使用固定新建 issue 地址，预填当前内容，不依赖跟踪 issue；最终由用户在 GitHub 提交。
- 保留复制备用路径。长 URL 按 parent spec 的预算切换为复制全文加打开空白 issue，不静默截断；复制失败可重试或手动复制。
- 每次打开重新生成、关闭丢弃；地址开关仅控制自动地址行，保留用户编辑，不把草稿写入账号、日志或 analytics。
- 一句提交前检查提示，不承诺绝对脱敏，不自动过滤或阻止用户自由文本。
- 复用现有帮助入口；不新增专用设置页或埋点。涉及搜索/深链时同步维护，新文案同步支持的语言。

## Validation / Acceptance

- 所有签到状态均能申请，缺少证据也不阻止提交。
- 覆盖每类入口及窄屏菜单的展示、正确账号传递、同一输入的报告一致性，以及账号删除和未保存账号编辑。入口打开不要求先签到/探测/保存。
- 复制与预填解码正文等于当前完整预览；覆盖编辑、长链接和复制失败。
- 自动字段不复制账号凭据；覆盖 origin 规范化与关闭开关、最近失败与历史状态映射。
- 生成和编辑不新增站点请求、不执行签到，不触发账号保存；关闭重开生成新报告。
- 实现后运行相关单元/组件测试和 i18n 检查；浏览器集成风险无法由这些验证时补 E2E。
