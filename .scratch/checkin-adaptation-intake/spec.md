# 签到适配申请：快速创建 issue 与辅助线索收集

- Status: resolved（切片 A/B 已实现；未发布）
- Parent design: `../checkin-method-discovery/spec.md`
- Updated: 2026-09-13

## 目标与取舍

核心目标是让普通用户快速提出签到适配 issue：打开入口 → 检查或编辑内容 → 到 GitHub 提交。只有站点地址和现象也可以申请，不要求先获得完整协议证据。

保留扫描以帮助维护者获取可能的签到线索。扫描是可选增强，失败、无结果或跳过都不阻止提交；不以线索直接认定兼容性或自动注册签到方法。

用户负责最终公开内容的确认。程序只做必要的字段选择和简单过滤，不建设通用脱敏框架、类型级存储隔离体系或专用 telemetry，不承诺“绝对不含敏感信息”。

## 实施切片

1. **01 / 切片 A：申请入口与 issue 提交闭环。** 从现有状态生成内容，不新增网络探测；可独立发布。
2. **02 / 切片 B：可选的“收集更多线索”。** 保留已知状态路由探测与前端 JS 路由扫描，依赖 01，但不阻塞 01 发布。

## Part 1 — 切片 A：快速创建适配 issue

### 入口与交互

- 首版同时接入下列已有签到相关界面，不把结果页入口推迟到后续切片。所有入口复用同一反馈组件和内容生成器，只传当前账号与可选的受控状态上下文，不分别实现表单。

| 位置 | 展示方式 |
| --- | --- |
| 账号编辑 → 签到配置（`AccountCheckInSection`） | 常驻次要入口；未知、不支持或选择失效时靠近状态说明，正常状态保持低调可用 |
| 账号列表 → 账号操作菜单（`AccountActionButtons`，覆盖使用此组件的弹出窗口、侧栏和选项页） | 在签到相关操作附近增加反馈菜单项；没有可用签到方法也不隐藏反馈 |
| 自动签到 → 执行结果（`ResultsTableRowActions`） | 失败、不确定、状态不可读和支持相关跳过原因提供直接次要操作，窄屏放入已有更多菜单；其他结果在更多菜单保留入口 |
| 自动签到 → 账号状态表（`AccountSnapshotTableRow`） | 在签到支持/就绪状态附近提供次要入口，用户无需先运行签到才能申请 |
| 已有签到检测或批量刷新反馈中的账号明细 | 能确定单个账号的行复用同一入口；只有总数的汇总链接到对应账号列表，不直接生成混合多账号报告 |

- 未识别/不支持用“申请签到适配”，已识别但异常或正常状态用“反馈签到问题”；共用同一表单，不增加申请类型选择步骤。反馈始终不要求先检测、签到、保存账号或扫描；同一处不重复放两个同义按钮。
- 首版实现时核对上述已有界面是否有账号级操作位置；复用现有菜单/状态行，不为覆盖入口新造批量刷新页面或独立流程。来源账号已删除时说明无法定位并引导回账号列表，不错误使用其他账号。
- 账号编辑入口使用当前表单的站点信息，其他入口使用对应账号信息；不自动保存账号，不丢失未保存的编辑，也不把表单内改过的地址与旧站点探测证据混为同一部署。
- 复用现有 Dialog；提供可选站点名称/现象描述、“附带站点地址”开关（默认开）和可编辑报告预览。
- 主按钮“创建 GitHub issue”：使用仓库固定的新建 issue 地址，预填标题与当前预览正文，由用户在 GitHub 确认提交。不得把打开页面提示为已提交成功。
- 次按钮“复制内容”：复制当前预览，适用于已有 issue、交流群或链接过长。复制失败保留可选中的正文并给出重试提示。
- 编码后的新建 issue URL 超过固定保守预算（默认 6,000 字符）时，不截断报告；提示用户复制全文，并打开不含报告正文的新建 issue 页面。正常预填也会把内容传给 GitHub，按钮旁用一句话说明。
- 每次打开从当前账号重新生成；关闭后丢弃本次草稿。弹窗内编辑不会保存到账号、日志或 analytics。
- 地址行独立显示，开关仅控制此自动字段；现象及其他报告文本可编辑，切换开关不覆盖编辑。开关不负责清除用户手写的地址，界面简短说明。
- 登记 `ACCOUNT_CHECK_IN_TARGET_IDS.feedback`。复用现有帮助入口写简短说明，不为本功能新建专用设置页；涉及现有搜索/深链时同步更新。

### 自动报告内容

- 扩展版本、平台、站点类型。
- 可选站点 origin：仅 HTTP(S)，去除用户名、密码、路径、查询参数和片段；地址无效时省略，不阻止申请。
- 当前候选方法的有效探测结论及受控原因码、选择状态。复用现有 inspection 投影；存在 `lastUnknownAttempt` 时不能把历史 matched 写成当前成功。无记录写“尚未探测”，无候选写“暂无已注册候选方法”。
- 用户填写的站点名称/现象，以及其对预览的编辑。

逐项拼接需要的字段，不序列化整个账号、请求或响应。自动部分不附带 token、Cookie、Authorization、账号备注、用户 ID 或原始后端 message。无需扫描用户自由文本并阻止提交；由用户检查最终内容。

生成与编辑报告不新增站点请求，也不触发重新探测或签到。打开 GitHub 是用户主动分享动作，不属于零网络生成承诺。首版不新增专用 telemetry，报告内容不进入已有埋点。

### 验收

- 各签到状态都能进入申请；缺少探测信息仍能生成和提交。
- 覆盖各入口的账号传递、异常/正常展示和窄屏更多菜单；相同账号及相同状态输入生成一致内容，账号已删除时不会串到其他账号。账号编辑入口不保存或丢失原表单修改，修改地址后不沿用旧部署证据。
- 有效状态与现有 inspection 一致，覆盖历史结论加最近失败。
- 预填正文解码后、复制结果与当前完整预览一致；长链接采用全文复制方案，失败不丢内容。
- 自动字段不会带出账号凭据；地址规范化和关闭开关有效。使用代表性案例测试，不要求证明任意输入绝对无秘密。
- 打开/编辑不触发探测或签到，报告编辑不进入账号保存；关闭重开恢复当前账号的新报告。
- 新 UI 文案同步支持的语言；实现时运行相关单元/组件测试和 i18n 检查。仅有浏览器集成风险时补 E2E。

## Part 2 — 切片 B：收集更多线索

### 用户流程

弹窗中提供可选按钮“收集更多线索”，旁边简短说明会使用账号会话查询本站签到状态接口、分析公开网页资源，可以跳过直接提交，无需额外确认向导。

结果作为可编辑区块加入报告，不覆盖用户已有编辑。显示完成、部分完成或未找到线索；失败保留已收集结果，始终可以创建 issue 或复制。关闭弹窗取消未完成请求，忽略迟到结果；不恢复后台任务。

### 扫描内容

1. **状态接口线索**：复用已有且已确认只读的 provider 状态接口；兄弟路由仅加入已有源码依据的固定状态查询 GET。实现时在路由表记录依据，没有依据的路由跳过，不阻塞其他扫描。无只读能力的 provider 不调用签到方法来代替。
2. **HTTP 线索**：在实际请求解析处采集状态码及有限顶层字段名，不假设 `detectWithStatusReadback` 还能拿到原始响应。不匹配状态结构时只标记结构未知；不输出响应体或后端 message。字段名仅取普通标识符，最多 20 个、每个 64 字符；常见凭据字段名省略。
3. **前端路由线索**：拉取同源入口 HTML 和其中直接引用的公开 JS，纯字符串解析，不执行脚本，不递归遍历全部 chunk。提取包含 `checkin`、`check-in`、`sign-in`、`redeem` 等关键词的 URL/路径字面量；只输出 pathname，移除查询参数、片段和 origin，去重，最多 30 条、每条 200 字符。跳过明显密钥形式的路径片段，不做通用秘密检测框架。

扫描到的路由仅是待调查线索，不自动请求它们，也不代表服务端实现了该接口。实际兼容性和签到执行语义由维护者后续核实。

### 简单运行边界

- 只运行上述已知状态 GET 和静态资源请求，不执行签到、登录自动化、兑换或 POST；不改变账号选择、探测存储与签到配置。
- 状态请求复用已有 AccessToken，不刷新令牌；Cookie 认证或缺少令牌时跳过需认证的状态查询，明确提示不可用，仍扫描公开资源。不借用浏览器当前登录会话；公开资源使用不带账号头、`credentials: omit` 的独立请求。只访问同源资源，拒绝重定向，避免跟到其他站点。
- 固定默认预算：总请求最多 12 次（含入口 HTML），其中状态查询最多 4 次；总下载最多 5 MiB，单请求 5 秒、总任务 20 秒。流式读取达到字节预算即取消，不能下载完再检查。实现可按实际资源调整固定值并说明，不增加配置 UI。
- 404/405、登录墙、WAF、超时或超预算都是可呈现的无结果/部分结果，不阻止申请，不自动重试。
- 结果只存在当前弹窗会话，不写入账号、备份、日志或 analytics；用普通局部状态和明确调用边界实现，无需改造全仓库持久化类型。

### 验收

- 已知路由与静态资源可产生用于 issue 的线索；无只读接口或扫描无结果仍可提交。
- 不执行变异请求，不主动请求扫描发现的路径，不写入账号或备份。
- 认证头/完整响应不进入报告；路径过滤、同源限制、公开资源不带会话有代表性测试。
- 请求/字节/时间预算、部分失败及关闭取消有效，失败不覆盖用户编辑。
- 增强报告保持可编辑，复制与 GitHub 预填使用用户看到的最终内容；文案与切片 A 一起维护多语言。
