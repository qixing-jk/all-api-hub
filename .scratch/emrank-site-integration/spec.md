# EMRank 账号站接入

- Status: ready-for-human
- Issue: https://github.com/qixing-jk/all-api-hub/issues/1711
- Updated: 2026-10-20

## 范围与边界

为 `https://emrank.tech` 增加独立账号站型 `emrank` 和专属适配族 `Emrank`。支持普通用户自动识别、保存账号、刷新额度、原生密钥管理、模型目录、每日签到、公告及兑换。不提供管理后台能力。

该站使用自定义 REST、裸 JSON / OpenAI 风格错误信封、HttpOnly Cookie 与 CSRF 标记，不能按 New API 或 Sub2API 协议接入。控制台、账号 `/api/*` 和推理 `/v1` 同源；`docs.emrank.tech`、`status.emrank.tech` 分别为文档和状态页，不是账号别名。

## 认证与恢复

唯一实现并验证的账号认证方式为 `__Host-gateway_session` Cookie。操作开始时固定 Cookie 快照，通过 `/api/auth/session` 核实身份，后续账号请求必须保持该身份；写请求附带 `X-Gateway-CSRF: 1`。过期会话需要用户重新登录网站，再恢复扩展操作。

系统访问令牌属于管理接口凭据，未证明可覆盖完整账号与签到契约，因此未作为账号认证方式实现。推理 API Key 与控制台 Cookie 分离，不能替代账号会话。

## 能力处置

| 能力 | 最终行为与限制 |
| --- | --- |
| 自动识别 | 主机名识别及实时会话身份验证，默认 Cookie；保存后可关闭网站标签页再刷新 |
| 余额 | `/api/account` 保存原子 Token 余额，以共享额度资产定义展示 M Token，支持结算后的负余额；不计入美元余额，不为未上线数据增加迁移 |
| 今日统计 | 未验证与扩展日期窗口一致的契约，显式标为不支持，不把滚动计数伪装为今日数据 |
| 密钥 | 完整分页清单、创建、合并编辑、启停、删除；额度使用 M Token，分别展示上游总量、剩余量、已用量，不以总量减已用量替代权威剩余值；有效期选项使用应用语言的可读标签；保留未改动字段和停用状态，同字段并发冲突在写前拒绝 |
| 密钥明文 | 按 `can_copy` 经 secrets 接口获取；不可复制的旧密钥标为 unavailable。创建后直接显示清单行，不弹一次性密钥交接框 |
| 模型目录 | 读取账号目录；展示用途、站点可用状态、上下文及已有规格，详情链接官网调用示例；嵌入、重排、决策按实际端点标记，模型行不提供不适用的生成/CLI 验证；用途/状态专用筛选暂缓 |
| 模型价格 | 通用原生额度计价：复用货币价格行展示每百万模型 Token 的输入和免费输出费率，复用现有权重进行账号内基础消耗排序；默认不显示加权估算或单独计算面板，用户等级/RPM 倍率未知时保留参考状态；不与货币或其他平台 Token 混比 |
| 签到 | 官方 `emrank:daily-checkin`；写前读取权威状态，仅 `already_claimed` 表示今日完成，开放前不能误判已签到；从 `record.reward` 保留原子 Token 和资产，成功/已领取结果显示 `+… M Token`，不依赖现金汇率；完整日历和历史暂缓 |
| 公告 | 读取 `/api/announcements?page=0` |
| 兑换 | 接入原生兑换接口并绑定身份快照，结果按适配器声明的原生资产显示到账额度；HTTP 和结果展示测试通过，未消费真实兑换码 |
| 邀请、计划、管理功能 | 普通用户邀请链接未注册；计划及管理后台不在本次接入范围 |

## 体验差距与后续边界

当前接入提供多账号聚合、余额刷新和自动签到，但仍有以下官网任务尚未覆盖，不能据此宣称体验全面优于官网。

| 暂缓能力 | 后续接入要求 |
| --- | --- |
| 模型用途、状态筛选及专用验证 | 复用模型目录筛选与验证框架；目前提供用途、规格及官网模型页入口，未内置逐模型调用示例或嵌入、重排、决策探测 |
| 密钥批量复制、删除 | 扩展已有共享多选工作流，覆盖删除确认、部分失败及结果不确定的恢复；当前支持单项操作，导入或导出不能替代批量整理 |
| 今日统计及用量追溯 | 官网提供概览和请求日志；缺口在本次适配。接入前核实 `Asia/Shanghai` 日期窗口、账单状态及历史覆盖，不把滚动 RPM 当作今日统计 |
| 完整签到历史 | 当前提供自动签到和原生资产奖励结果；完整日历、累计获得额度及开放窗口展示暂缓 |

模型目录归属不等同于已核实的模型发布者；站点可用状态与本地验证状态分别展示，缺失规格不推断。

## 共享修复

- 请求头按大小写不敏感规则合并，避免严格网关收到重复 Content-Type。
- 原生密钥编辑器在依赖的清单重载期间禁用保存。
- 公共写操作出口统一区分明确拒绝与结果不确定。超时、取消、未知适配器异常和已接受写入后的失败不能自动重放；不确定警告在只读对账后保留，直到用户关闭。
- Cubence、FoxCode 保留业务拒绝消息；Krill、Cubence、Dahl、FoxCode、EMRank 转发协议确认写入的证据，避免后续失败覆盖先前成功。

## 验证与维护入口

单元和 HTTP 边界测试位于 `tests/services/apiService/emrank/`、`tests/services/apiAdapters/emrank/`、`tests/services/accountSiteOnboarding/contentSession/emrank.test.ts` 及共享请求、写操作和编辑器测试中。

可复跑的开发扩展流程为 `pnpm e2e:cdp:emrank`（提供方只读，创建并清理本地测试账号）；显式 `--mutate` 才创建、修改和删除一次性站点密钥。不执行推理、登录、兑换或签到领取。默认流程并不验证真实写操作。

验证边界：真实账号的密钥样本为无限额度，有限额度由上游剩余值与总量减已用量不相等的 HTTP 用例覆盖；停用模型、过期会话的现场恢复及公告内容和排序的完整对齐尚无现场验证。真实兑换、签到奖励领取和推理不由只读流程验证。

原始协议、截图、TDD 记录、真实写操作的状态读回及清理结果保留在本地排除的 `evidence/` 中。它们不属于公开交付；实际命令结果、版本和证据缺口以本次验收报告为准。支持目录与根 README 的中文、英文、日文条目同步维护。

模型原生额度与货币价格采用不同计划，共用额度资产定义连接账号余额、密钥额度及计价展示。现有 Xiaoen Credits 保持原有语义。
