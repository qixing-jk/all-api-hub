自动签到与签到监控

让支持签到的聚合账号每天按时签到、累计额度，并保存最近一次执行结果，避免人工忘记操作。

功能概览

  • 签到状态检测：添加或刷新账号时自动判断站点是否带签到入口，无需手动开启“签到检测”。
  • 自定义签到入口：签到页面不在标准路径时，可在账号的“签到配置”中填写“外部签到站点 URL”。
  • 自动签到调度：基于浏览器后台定时能力执行 每日一次 的常规自动签到，并对 当日失败账号 按设置自动重试。
  • 执行记录：保存最近一次执行结果，包含成功、失败、跳过原因、最后运行时间和下次计划，可在“自动签到”页面查看；当前不是多日历史日志。

使用前提

  1. 在 账号管理 中已添加账号，并成功刷新或识别一次。
  2. 确认账号登录凭据有效。选择“自动选择”时，尚未选出方式的账号可在每日任务中重新检测；确认可用方式后才会执行签到。具体要求见下方“支持站点与认证要求”。
  3. 在 账号管理 → 编辑账号 的“签到配置”中确认出现“启用每日自动签到”。只有支持内置签到的账号会显示此开关。
  4. 浏览器需支持后台定时能力；浏览器关闭、设备休眠或后台策略变化时，不保证准点执行。

设置步骤

1. 账号级开关

  • 打开任意账号 → 编辑账号 → “签到配置”。
  • 支持内置签到的账号会显示：
    • 签到方式：选择“自动选择”后，系统会在尚未选出方式或原方式明确失效时按需重新检测；只有能唯一确定适用方式时才自动选择或切换。手动指定方式会固定你的选择。
    • 启用每日自动签到：默认开启；关闭后即使全局启用，该账号也不会参与自动签到。
    • 外部签到站点 URL（可选）：签到页面不是标准路径时填写。所有账号都可以按需配置外部签到入口。
    • 自定义充值/兑换页面 URL（可选）及“使用外部签到时同时打开充值页面”。
  • 账号表单没有“签到检测”开关，签到状态会在账号刷新或识别时自动读取。
  • 自动重新检测需要同时开启全局和账号的自动签到，随每日任务执行（也包括打开界面时提前触发的每日任务），同一账号两次自动检测至少间隔 24 小时。网络错误、超时或登录过期不会被当作方式失效。
  • 主动点击“重新检测签到方式”不受自动检测冷却限制，只查找方式，不直接签到；账号编辑框中的检测结果随保存生效。

2. 全局时间窗口

在 设置 → 签到与兑换 → 自动签到 面板中：

选项说明
启用自动签到控制每日计划和自动重试；关闭后仍可手动批量“立即执行”，也可使用单账号“快速签到”。
打开界面时提前触发今日签到默认开启。打开弹窗、侧边栏或设置页时，若今日计划尚未执行且当前时间在窗口内，会提前触发一次每日运行。
自动签到完成后刷新数据和界面签到成功后刷新账号数据并更新界面；它不是系统或第三方任务通知的开关。
时间窗口开始 / 结束每日计划允许的本地时间范围，允许跨午夜。
计划模式在窗口内随机选择一个时间运行；也可选“固定时间”。
固定时间仅在“固定时间”模式下生效。
重试策略默认开启，仅每日计划中可重试的失败账号在当天自动重试；手动“立即执行”不会创建自动重试队列。
重试间隔（分钟）仅在重试开启时生效。
每日最大尝试次数包含首次每日运行，不是额外重试次数。
查看签到历史 / 打开记录打开自动签到结果页；保存的是最近状态，不是多日历史档案。
恢复默认将自动签到设置恢复为扩展提供的默认配置。

设置保存后立即生效，无需重启扩展；升级会保留你已保存的设置。

3. 查看执行状态

  • 打开 设置页左侧“自动签到” 页面，可查看最近一次执行结果、下次每日计划时间和（如有）下次重试计划时间。
  • 结果区会显示可参与、已执行、成功、失败和跳过等状态；页面底部还会显示“账号检测状态”、提供方、跳过原因和最近结果。
  • 点击“立即执行”可为符合条件的账号手动运行一次，不受全局自动签到开关影响；账号仍需启用且满足签到条件。只处理单个账号时，可使用账号“…”菜单中的“快速签到”。
  • 弹窗或侧边栏顶部的“快速签到”日历图标会打开签到页面并发起一次手动批量签到。
  • 失败结果行可按需使用“重新尝试”“手动签到”“外部签到”“打开网站”等操作；手动签到需要你在站点页面完成。
  • “待确认”结果会提供“验证状态”操作。它只读取当天状态并更新账号配置，不会直接重复提交签到；如果需要登录或修复认证，请先打开网站完成登录，再重新验证。
  • 需要反馈问题时，在账号菜单或结果行选择“反馈签到问题”或“申请签到适配”，检查报告后复制或前往 GitHub 提交。

4. 处理检测与执行状态

账号的签到配置会保留你的手动方法选择和自定义 URL，不会因为网络错误或登录过期而切换方法。根据状态采取对应操作：

状态含义下一步
已确认已确认选中的签到方法可用保持自动签到，通常无需操作
需要选择检测到多个候选方法选择一次方法，或保留现有选择
未知本次检测未能完成点击重新检测
不支持没有确认可用的内置方法使用自定义签到 URL、手动签到或申请签到适配
已禁用站点明确关闭了该方法保留方法，关闭自动签到或改用手动方式
状态不可读方法仍存在，但今天的状态暂时无法读取保留选择和自动签到开关，稍后重试或手动确认
待确认请求结果无法可靠确认点击验证状态；需要认证时打开网站登录，禁止直接盲目重试

工作原理

  1. 配置写入：自动签到配置保存到本地偏好后，立即通知后台重新排程。
  2. 调度初始化：扩展启动时创建浏览器后台闹钟监听：
    • 每日闹钟：常规自动签到，每天最多一次。
    • 重试闹钟：仅在当日常规运行存在失败账号时触发，只重试失败账号。
  3. 执行流程：
    • 每日任务先检查启用账号的自动选择状态；需要重新检测且冷却已结束时，先检测并保存结果，再检查签到方式、凭据和当天状态。没有适用候选、多种方式无法确定或检测未完成时，不会随意选择一种执行。
    • 已有方式仍适用时继续使用。执行前的只读检查若确认旧方式不支持，可在冷却允许时检测并选择唯一替代方式；如果签到请求已经发出、结果待确认，则先核验结果，不会换一种方式再次提交。
    • 调用对应站点的内置签到提供方，并记录成功、失败、待确认或跳过原因。
    • “成功”和“今日已签到”都视为成功；真正新签到成功后还会刷新账号数据。
    • 仅可安全重试的失败会在重试开启时进入当日队列；认证失败、权限不足或站点不支持签到状态读取时不会自动重试。
    • 自动重试会先确认当天状态，再决定是否提交签到。状态暂时无法读取时，本轮不会提交，但会在每日最大尝试次数内继续等待后续重试。
  4. 重新调度：常规每日运行完成后，会为下一天重新计划每日闹钟；当日存在失败账号且启用重试时，会计划重试闹钟。

支持站点与认证要求

以下站点有已适配的签到方式，是否可用仍以账号检测结果为准：

站点类型是否内置自动签到认证要求
new-api有Access Token（Cookie 账号可用 Cookie 会话）与账号 ID
ModelFlare有Cookie 会话与账号 ID
Veloera有Access Token 或 Cookie，以及账号 ID
anyrouter有Cookie 会话或浏览器登录上下文，以及账号 ID
wong-gongyi有Access Token 或 Cookie，以及账号 ID
voapi-v2有保存的仪表盘 JWT（Access Token）
sub2api有已检测到的 Sub2API Pro 或 Denxio 签到方式所需的有效登录凭据
AgentRouter（agentrouter.org）有检测到登录签到后，在账号签到配置中选择对应的 GitHub 或 LinuxDo 登录方式；按提示完成浏览器登录或授权，并以执行结果确认签到状态

AgentRouter 登录签到的限制

AgentRouter 的签到发放在一次全新的 OAuth 登录过程中完成，而浏览器登录用的是当前浏览器里已经登录的 GitHub 或 Linux DO 身份，不是每个账号各自的凭据。因此：

  • 登录方式必须显式选择。添加账号时会根据该账号在站点上已绑定的 GitHub / Linux DO 身份自动预选；若账号同时绑定了两种、或部署未返回绑定信息，则保持未选择。未选择时签到会直接失败并提示先选择登录方式，扩展不会替你猜一个默认值。
  • 同一个登录方式同一时间只能由一个启用自动签到的 AgentRouter 账号使用。两个账号都用 GitHub（或都用 Linux DO）时，它们会共用同一个浏览器身份，第二个账号只会得到身份不匹配的错误，并扰乱共享的登录会话。
  • 冲突时的表现：账号设置里，已被其他账号占用的登录方式会置灰并说明原因；后台执行时，非归属账号会被跳过并在结果里注明原因。归属判定优先采用实际证据：浏览器上次登录成功的是哪个账号，哪个账号就持有该登录方式；其次是尚未尝试过的账号；账号 ID 只作最后兜底。因此即使两个账号曾抢同一个登录方式，扩展也会自动收敛到真正能登录的那个。
  • 如何解绑：把该登录方式改为另一个（例如另一个账号用 Linux DO、本账号用 GitHub），在账号设置里把登录方式改为「未选择」清空，或先停用/删除占用它的账号。登录方式置灰只作提示，不会阻止你修改或清空本账号自己的选择。

部署差异

即使站点类型匹配，具体部署也可能是魔改版本：可能没有提供预期的签到接口（例如返回 404/405）、认证方式不同或有人机验证。不要因为某站“兼容 New API”就推断它有内置自动签到。

其他站点若未检测到可用方式，可配置外部签到 URL、手动签到，或申请签到适配。

最佳实践

  • 时间窗口建议：设置在站点低峰期（例如凌晨），提高成功率。
  • 浏览器需保持运行：浏览器完全关闭或设备休眠时不会签到，也不会主动唤醒设备；唤醒后错过的闹钟可能延迟触发，且不会补签前一天。闹钟行为可参考 Chrome Alarms API。
  • 外部签到和手动签到：外部签到只打开你配置的页面，页面成功打开后只记录“今天已打开”，不会提交或验证网页内是否真的签到；手动签到则打开站点原生签到页，需要你在网页中完成签到。
  • 多设备注意：WebDAV 和 GitHub Gist 同步账号与偏好，但不共享当天签到状态、最近结果和浏览器计划；建议只在一台设备上开启自动签到。
  • 异常通知：每日计划与自动重试完成时会发送任务通知（在 设置 → 通用 → 通知 配置）；手动“立即执行”和单账号“快速签到”不会发送计划任务通知。

提示需要登录或人机验证按提示打开站点页面完成验证后再重试，不要以为扩展已经替你签到。
