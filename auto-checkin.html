自动签到与签到监控

让支持签到的聚合账号每天按时签到、累计额度，并保存最近一次执行结果，避免人工忘记操作。

功能概览

  • 签到状态检测：添加或刷新账号时自动判断站点是否带签到入口，无需手动开启“签到检测”。
  • 自定义签到入口：签到页面不在标准路径时，可在账号的“签到配置”中填写“外部签到站点 URL”。
  • 自动签到调度：基于浏览器后台定时能力执行 每日一次 的常规自动签到，并对 当日失败账号 按设置自动重试。
  • 执行记录：保存最近一次执行结果，包含成功、失败、跳过原因、最后运行时间和下次计划，可在“自动签到”页面查看；当前不是多日历史日志。

使用前提

  1. 在 账号管理 中已添加账号，并成功刷新或识别一次。
  2. 账号站点类型属于下方“支持站点”中的精确类型之一。
  3. 在 账号管理 → 编辑账号 的“签到配置”中确认出现“启用每日自动签到”。只有支持内置签到的账号会显示此开关。
  4. 浏览器需支持后台定时能力；浏览器关闭、设备休眠或后台策略变化时，不保证准点执行。

设置步骤

1. 账号级开关

  • 打开任意账号 → 编辑账号 → “签到配置”。
  • 支持内置签到的账号会显示：
    • 启用每日自动签到：默认开启；关闭后即使全局启用，该账号也不会参与自动签到。
    • 外部签到站点 URL（可选）：签到页面不是标准路径时填写。所有账号都可以按需配置外部签到入口。
    • 自定义充值/兑换页面 URL（可选）及“使用外部签到时同时打开充值页面”。
  • 账号表单没有“签到检测”开关，签到状态会在账号刷新或识别时自动读取。

2. 全局时间窗口

在 设置 → 签到与兑换 → 自动签到 面板中：

选项默认值说明
启用自动签到开控制全局每日计划、自动重试和自动签到页的批量“立即执行”；关闭后不会创建相关计划，也不会执行批量签到。账号菜单中的单账号“快速签到”仍可运行。
打开界面时提前触发今日签到关打开弹窗、侧边栏或设置页时，若今日计划尚未执行且当前时间在窗口内，会提前触发一次每日运行。
自动签到完成后刷新数据和界面开签到成功后刷新账号数据并更新界面；它不是系统或第三方任务通知的开关。
时间窗口开始 / 结束09:00 / 23:00每日计划允许的本地时间范围，允许跨午夜。
计划模式随机在窗口内随机选择一个时间运行；也可选“固定时间”。
固定时间09:00仅在“固定时间”模式下生效。
重试策略关仅每日计划失败的账号在当天自动重试；手动“立即执行”不会创建自动重试队列。
重试间隔（分钟）30仅在重试开启时生效。
每日最大尝试次数3包含首次每日运行，不是“额外再重试 3 次”。
查看签到历史 / 打开记录按钮打开自动签到结果页；保存的是最近状态，不是多日历史档案。
恢复默认按钮恢复上表的默认值：开启、09:00～23:00、随机、重试关闭。

设置保存后立即生效并重新排程，无需重启扩展。

3. 查看执行状态

  • 打开 设置页左侧“自动签到” 页面，可查看最近一次执行结果、下次每日计划时间和（如有）下次重试计划时间。
  • 结果区会显示可参与、已执行、成功、失败和跳过等状态；页面底部还会显示“账号检测状态”、提供方、跳过原因和最近结果。
  • 全局“启用自动签到”开启时，点击“立即执行”可以为全部符合条件的账号手动运行一次；全局关闭时不会执行这次批量签到。只想处理单个账号时，在账号“…”菜单点击“快速签到”，该入口不受全局开关限制。
  • 弹窗或侧边栏顶部的日历图标（提示“快速签到”）会打开设置页中的自动签到页面，并在全局开关开启时立即执行；侧边栏复用弹窗入口，没有独立的自动签到页面。
  • 失败结果行可按需使用“重新尝试”“手动签到”“外部签到”“打开网站”等操作；手动签到需要你在站点页面完成。
  • “待确认”结果会提供“验证状态”操作。它只读取当天状态并更新账号配置，不会直接重复提交签到；如果需要登录或修复认证，请先打开网站完成登录，再重新验证。

4. 处理检测与执行状态

账号的签到配置会保留你的方法选择和自定义 URL，不会因为一次检测失败而静默改回其他方法。根据状态采取对应操作：

状态含义下一步
已确认已确认选中的签到方法可用保持自动签到，通常无需操作
需要选择检测到多个候选方法选择一次方法，或保留现有选择
未知本次检测未能完成点击重新检测
不支持没有确认可用的内置方法使用自定义签到 URL 或手动签到
已禁用站点明确关闭了该方法保留方法，关闭自动签到或改用手动方式
状态不可读方法仍存在，但今天的状态暂时无法读取保留选择和自动签到开关，稍后重试或手动确认
待确认请求结果无法可靠确认点击验证状态；需要认证时打开网站登录，禁止直接盲目重试

工作原理

  1. 配置写入：自动签到配置保存到本地偏好后，立即通知后台重新排程。
  2. 调度初始化：扩展启动时创建浏览器后台闹钟监听：
    • 每日闹钟：常规自动签到，每天最多一次。
    • 重试闹钟：仅在当日常规运行存在失败账号时触发，只重试失败账号。
  3. 执行流程：
    • 读取账号并构建快照，筛选账号是否已启用、已完成刷新/识别、账号级开关开启、站点类型有内置提供方且凭据可用。
    • 调用对应站点的内置签到提供方，并记录成功、失败、待确认或跳过原因。
    • “成功”和“今日已签到”都视为成功；真正新签到成功后还会刷新账号数据。
    • 仅可安全重试的失败会在重试开启时进入当日队列；认证失败、权限不足或站点不支持签到状态读取时不会自动重试。
    • 自动重试会先确认当天状态，再决定是否提交签到。状态暂时无法读取时，本轮不会提交，但会在每日最大尝试次数内继续等待后续重试。
  4. 重新调度：常规每日运行完成后，会为下一天重新计划每日闹钟；当日存在失败账号且启用重试时，会计划重试闹钟。

支持站点与认证要求

当前内置自动签到提供方包含以下七个精确站点类型：

站点类型是否内置自动签到认证要求
new-api有Access Token（Cookie 账号可用 Cookie 会话）与账号 ID
ModelFlare有Cookie 会话与账号 ID
Veloera有Access Token 或 Cookie，以及账号 ID
anyrouter有Cookie 会话或浏览器登录上下文，以及账号 ID
wong-gongyi有Access Token 或 Cookie，以及账号 ID
voapi-v2有保存的仪表盘 JWT（Access Token）
sub2api有Sub2API Pro 的 Access Token 或可恢复的登录会话

部署差异

即使站点类型匹配，具体部署也可能是魔改版本：可能没有提供预期的签到接口（例如返回 404/405）、认证方式不同或有人机验证。不要因为某站“兼容 New API”就推断它有内置自动签到。

以下站点类型当前没有内置自动签到提供方（仍可配置外部签到 URL，或使用手动签到）：one-api、one-hub、done-hub、v-api、旧版 VoAPI、Super-API、Rix-Api、neo-Api、AIHubMix、sharedchat、openrouter 等。

最佳实践

  • 时间窗口建议：设置在站点低峰期（例如凌晨），提高成功率。
  • 浏览器需保持运行：浏览器完全关闭或设备休眠时不会签到，也不会主动唤醒设备；唤醒后错过的闹钟可能延迟触发，且不会补签前一天。闹钟行为可参考 Chrome Alarms API。
  • 外部签到和手动签到：外部签到只打开你配置的页面，页面成功打开后只记录“今天已打开”，不会提交或验证网页内是否真的签到；手动签到则打开站点原生签到页，需要你在网页中完成签到。
  • 多设备注意：WebDAV 只同步账号与偏好，自动签到的当天执行状态、最近结果和浏览器闹钟不会跨设备共享；多台设备同时开启计划仍可能重复签到。
  • 异常通知：每日计划与自动重试完成时会发送任务通知（在 设置 → 通用 → 通知 配置）；手动“立即执行”和单账号“快速签到”不会发送计划任务通知。

常见问题

结果含义是否自动重试
成功 / 今日已签到本轮确认完成签到，或站点确认今天已经签到否
失败接口、认证、验证、网络或站点响应失败仅每日计划、已开启重试且系统判断可安全重试时
待确认请求可能已经提交，但站点结果无法可靠确认；系统只做一次只读状态核验，不会直接重发签到否，使用“验证状态”或打开网站修复认证
已跳过账号禁用、未完成识别、账号级关闭、无提供方或凭据不足否
问题排查方法
页面显示“未计划 / 已禁用 / 无待重试”“已禁用”：全局自动签到开关关闭。
“重试未启用”：未开启重试策略。
“无待重试”：已开启重试但当前没有失败账号。
“未计划”：已启用但浏览器不支持后台定时或闹钟尚未创建/被清除；尝试重新保存设置。
某账号每天失败或显示“已跳过”检查“账号检测状态”里的提供方与跳过原因：账号未禁用、已完成刷新/识别、账号级开关开启、站点类型有内置提供方且凭据可用。
执行结果提示 Access Token 无效通常表示该账号的 Access Token 已失效或被撤销。
处理：先在浏览器中登录该站点，然后在「账号管理 → 编辑账号」中重新“自动识别/刷新 Access Token”。若站点禁用 Token 或无法获取 Token，可改用 Cookie 认证，或关闭该账号的自动签到改为手动。
New API 返回 404/405该部署没有提供预期签到接口，不代表插件故障；可改用手动签到或外部签到。
提示需要登录或人机验证按提示打开站点页面完成验证后再重试，不要以为扩展已经替你签到。
多个账号重复签到多台设备同时运行且执行状态不共享时可能重复；建议只在一台设备开启自动签到计划。
外部签到没生效外部签到只负责打开页面，不会自动提交或确认成功；请确认 URL 可在浏览器直接访问，并人工在页面完成签到。
